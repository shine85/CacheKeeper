# 独立手机诊断

适用当前项目的 iOS 16–17 RootHide 环境。解压完整工具包，在该目录运行一次：

```sh
sh run.sh
```

出现 `state: started` 只表示后台进程已成功创建报告；可以退出终端，正常使用百度网盘并滑动照片。约 90 秒后，将输出路径里的 `report.json` 发回。最终 `state` 为 `complete` 或 `partial`；`partial` 的读取失败、时间预算与未覆盖范围都保留在同一文件中。每次运行使用独立目录，不覆盖旧报告。

工具读取系统注册的全 APP 容器计划，复用现有只读容量服务统计目录和 stat 元数据、列出大占用；共享根只测一次，单 APP 的共享归属量不能跨 APP 相加。容量不是可删除量，未覆盖根不当成零。既有的企业微信排除继续生效。

同时读取有限的插件技术状态，按固定名称记录进程 PID/启动时间变化，以及系统已经生成的 crash/hang 文件类型、大小和时间。系统日志正文、原文件名和路径不导出；进程名匹配不证明 bundle 身份，也不证明界面响应正常。工具没有线程栈，不能单凭报告确定照片浏览卡顿根因。

工具只在自身输出目录写容量请求和报告，不改插件/APP 配置，不清理资源，不读取业务文件内容，不附加进程、不读取进程内存、不触发系统采样。状态记录的原有时间和错误保持，不包装为本轮新验证。

手机不需要 Python、jq 或安装新依赖。启动脚本使用已存在的 RootHide `jbroot`/`rootfs` 命令，在解压目录创建指向当前越狱根的 `.jbroot` 链接，满足 `@loader_path/.jbroot/usr/lib/libroothide.dylib` 的装载。目标库、签名或链接不满足时必须失败，不回退扫描随机根或安装依赖。RootHide 文档要求的四项可执行权限仅用于独立工具访问系统注册/目录元数据；无 `get-task-allow`、`task_for_pid` 或进程调试权限。

开发验证必须分别记录：macOS 真实文件/容量/后台进程行为、iOS 双架构编译和签名/依赖检查、当前手机实际运行。前两项不证明第三项。`kern.proc` 和系统注册提供者属于系统工具 SPI，拒绝访问时报告 `unavailable`，不伪造空的成功清单。

新文件，无旧版本可备份。
