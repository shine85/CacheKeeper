# 全 APP 大占用清单与后续治理

本文件对应 [154.1 反馈续修计划](superpowers/plans/2026-11-16-154-feedback-and-product-completion.md)。当前是整组开发中的实现说明；真实原生测试、RootHide 编译、deb 和新版本手机验收尚未完成。不能由本文推定下一版本已经发布或资源已经回收。

## 本轮实现的范围

诊断页的同一次系统登记会同时生成展示用 APP 列表和全部有效登记清单。清单包括被展示规则过滤的系统条目，以及 home、App Group、extension 的关联；不因没有独立主容器而丢弃其他关系。每次采集重新取得登记，继续复用原安装身份缓存、关系冲突处理和既有预算。主清单仍是保存记录汇总，不自动发起全机扫描或资源操作。

诊断 JSON 顶层 `storageInventory` 汇总系统登记与已配置条目，保留原扫描时间、测量状态、覆盖缺口、当前开关、选择和排除。系统登记不证明文件系统可访问；`currentInstallationMatch=notChecked` 明确保存测量尚未关联本次安装身份。未在本次登记中出现不直接等于卸载，缺测不补零。

共享关系使用同一份清单内的 `resource-N` 标记，只有登记 URL 字符串完全相同时相等。标记不输出原容器地址或组标识，也不代表 inode、硬链接、APFS 克隆或物理空间去重。不同采集不能把标记直接当稳定资源 ID。

## 两条开发队列

| 字段 | 纳入范围 | 执行条件与后续工作 |
| --- | --- | --- |
| `standardPolicyCandidates` | 符合既有标准目录政策且有保存逻辑字节的资源行；规则来源复用 Policy | 保留当前开启、目录选择、自动发现、排除状态；只有配置允许时标为等待执行前复核，仍要检查当前安装、容器、保留项、进程时序和实际效果 |
| `unknownResourceEvidence` | 有保存逻辑字节但尚无标准用途契约的有效资源行 | 按占用推进真实 owner、资源用途、引用/保留集合、重取来源及恢复契约；继续保留数据，不按大小、后缀或 SDK 名称取得清理资格 |

两队列均按单个保存行的逻辑字节降序排列，不设 APP 白名单或固定两个样本优先。相同值按 APP、路径、观察行号稳定排序。原始保存行可能互相重叠，所以没有可相加的全 APP 物理或可回收总量。API 回执摘要只表示曾观察到的阶段，不建立资源删除契约。

资源发现预扫和输出均限制每 APP 前 16384 行，重复缓存根通过集合合并，政策路径每 APP 计算一次。预算外行不参与自动发现，覆盖截断和精确省略行数保留。这个预算保证聚合工作有限，不证明原扫描完整或底层文件已经全部测量。

## 从清单推进到实际回收

开发侧先检查当前安装和观测覆盖，再从有标准政策的已授权资源开始核验现有引擎。未知大资源同时补归属与恢复证据，不能因为百度、Swiftgram 的故障尚未闭合而暂停其他 APP。新增或升级 APP 会进入新登记；资源契约的持久失效和自动重新核验仍是后续能力，当前清单不能宣称任意未来 APP 已适配。

每项要分别形成可发现、可回收、可限制写入、可关闭恢复的证据。缓存动作完成后用 [SDK 资源前后核验](2026-11-16-SDK资源前后核验.md) 中的开发工具核对已证明 owner 的范围，并与操作历史关联。工具本身不证明 owner、不授予删除许可，也不把对象消失自动归因为插件或物理释放。

必要数据、未知共享引用、下载/草稿唯一副本和未知用途目录继续保留。已授权标准缓存也须验证三轮存量回收、同负载限制新增、关闭恢复和业务保持；iOS 16 与 17 的手机结果分别记录。逻辑字节、已分配量、对象移除量和可用空间变化是不同指标，不能用单次差值互相替代。

## 当前验证边界

实现已有真实保存 plist 到生产 Diagnostics 再到 JSON 的原生测试入口，覆盖完整登记、系统条目、共享关系矛盾、配置/排除、零与缺测、时间与隐私、预算截断及重复根。代码定向复审已修正两项关系一致性和工作预算问题。

Windows 不能执行该 Foundation/POSIX 入口，当前结果为 UNAVAILABLE，尚无本组原生 GREEN；后续由同一整组提交的 macOS Actions 执行指定旧行为 RED、当前 GREEN、既有 SDK/UIKit 回归及 RootHide 编译。具体提交、构建、包和手机证据在成功后另行填入交付记录。
