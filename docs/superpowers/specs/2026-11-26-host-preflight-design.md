# 五 APP 宿主集中预检

用户要求持续完成有效的集中采集工具，不反复要求 SSH 和重复导出。现有报告的 QQ/京东/Swiftgram 宿主仍是211.1、百度202.1；原因尚未区分。先集中执行已存在的只读宿主观察，判断实际加载版本、已有共享访问、配置可读性和已有发布状态。

## 实现选择

复用 `AxsCacheKeeperHostEvidenceClient`，只在 Preferences 新增批次管理与页面，不更改服务端、协议、权限或缓存策略。它不是被拒的私有资源取证替代路径，不附加进程、不读其他进程内存，不调用网络probe、资源清理或未知宿主方法。

诊断页新增“五 APP 宿主集中预检”，一键向抖音、QQ、百度网盘、京东、Swiftgram发送现有请求。5分钟内用户依次打开目标APP，再回页面查看；不自动启动或关闭APP。请求留在Preferences原页面存续期间，后台暂停UI定时器，返回恢复poll；真正离页取消未完成项并释放tokens。超时不表示未注入。

## 状态与保存

每APP独立显示 pending/observed/timedOut/cancelled/transportError/invalidResponse/clockChanged；生产校验继续走原projection。返回observed仍为未经认证的自身技术信号，不代表清理/限写/资源范围成功。版本与面板版本比较用原函数；配置和旧发布错误原样展示。

终态回执保存到现有 `Status/<bundle>.hostObserved.plist`，沿用总报告现有读取。保存失败保留当前结果并明确error code，不改配置、不创建越狱目录、不把内存完成当保存完成；页面可单独重试保存。已有成功项不会被自动再次请求。新一轮由用户明确点开始，重新生成请求并清除页面旧结果。

## 验证

批次层使用真实Foundation文件写入与现有Darwin notify客户端；覆盖并行独立目标、begin失败、超时/取消/重启、写盘失败与恢复、旧版本信号和不触发策略。UIKit覆盖入口、五项显示、后台保留/返回刷新、取消离页、保存失败提示与PDF/容量入口兼容。云端原生/UIKit/Theos全部通过再交付，手机尚未验证则明确区分。

完整目标仍缺五APP私有资源契约和实际效果。此修复只闭合“本轮插件有没有响应且报告是否可用”的第一阶段。用户已有继续实现和整组验证后发布授权，不重复询问实现方式。新文件无旧版可备份。
