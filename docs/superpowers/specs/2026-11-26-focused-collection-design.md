# 五 APP 集中采集设计

用户已于 2026-11-26 同意“一次部署、五 APP 集中操作、统一导出”的方向，最终目标仍是补齐真实缓存适配证据。当前继续受此前自动安全审核拦截约束；本地准备不代表运行时采集已经可执行。

## 本轮可实施部分

沿用 `scripts/collect_device.py`，增加明确的离线准备入口，将终态静态报告中的抖音、QQ、百度网盘、京东、Swiftgram 汇总成一个 ZIP。复用现有报告校验，不加载 SSH adapter；不包含服务器、附加脚本、设备命令或任意执行入口。

报告包包含五 APP 当前保存身份与证据来源、可验证静态回执摘要、未完成的适配条件及中文说明。只输出固定字段与脱敏技术元数据，不复制全部应用清单、会话信息、路径或二进制对象。已保存证据须绑定来源报告 SHA，历史引用须验证相应报告和回执；不得把历史身份称为手机当前实时状态。

## 尚不能交付的部分

手机本地运行时执行、初始化/所有者/全部写入入口观察、真实保留规则和清理范围验证仍不可执行。该 ZIP 必须明确标为“离线准备报告包”，不能命名或展示成“手机采集工具”。手机操作顺序仅在执行器实现、测试通过且可执行后生成；此时不要求用户重新上传旧工具或逐 APP 操作。

## 不变量与验收

- 五 APP 均有结果项；缺身份、partial、unknown 单独保留，不能以空值或无匹配替代成功。
- ZIP 成功写出只证明离线准备完成，五 APP 适配验收一律仍是未验证。
- 输出只能是新文件；失败不能覆盖现有文件；输入坏链、摘要不符、引用越界必须在创建包前拒绝。
- 真实文件回归覆盖 CLI 离线分支、不加载传输、历史回执/篡改、缺身份、中文 ZIP 内容与重复输出；再对当前实际三报告链生成并核验包。

文件为新增，无旧版本可备份。
