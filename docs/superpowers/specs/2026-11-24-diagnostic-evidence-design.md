# 诊断证据链修复设计

## 意图

修复 202.1 真机反馈和当前实现暴露的诊断口径缺口，使导出的数据能区分完整测量、部分下界、来源未知和真实动作回执。成功条件是：Gurd 只有在证明观测范围等于宿主真实清理范围且 before/after 均完整时才调用宿主清理；写入限制状态只描述已接入的 SDWebImage 路径；Swiftgram 跨轮失败保留可诊断摘要；导出报告中的全容器容量来自最新已完成的只读重测。

## 范围与排除项

- Gurd：先证明并固定宿主清理实际覆盖的候选范围、排除条件和身份；实现同进程分片续采；partial 只表示已观察字节的下界，永远不能授权宿主调用。无法证明范围时明确 blocked，不调用 `clearCacheExceptWhitelist:`。
- 写入限制：设置说明和回执解释只承诺已适配的 SDWebImage 磁盘写路径。`attempts` 与 `blocked` 必须来自真实写入观察；缺失字段为 unknown，不能从清理 API 完成数推导。
- Swiftgram：在最近轮次历史中保存当前扫描诊断的封闭投影，包括失败阶段、错误域、错误码、聚合数及截断状态；不保存私有路径、错误文本或文件内容。旧轮次缺少字段仍标 unknown，不回填成功或零错误。
- 导出：全容器重测终态须与汇总时绑定的 epoch 一致；重测开始会使旧报告失效。取消未确认、仍 running、结果不可读或未重新汇总时不得导出为最新结果；局部根失败保留原失败状态，不补零。
- 不动：抖音 ALog 三轮、其余 12 个无回执 APP、D 后数据完好性，以及任何宿主资源清理范围之外的用户数据。

## 约束与证据边界

- “提交”在本设计中专指调用宿主 `clearCacheExceptWhitelist:`，不指 Git commit。
- 固定宿主代码表明 `clearCacheExceptWhitelist:YES` 保留白名单并清理其余候选；当前没有足够证据证明静态白名单子树等价于真实清理候选集。不能以缩小遍历范围来掩盖范围不一致。
- 当前认证目标限定为 `com.ss.iphone.ugc.Aweme`、版本 `41.2.0`、build `412021`。实现身份继续核对当前代码中固定的类/selector/type/实现地址和五个代码窗口哈希；这些窗口哈希不是整份宿主二进制哈希。任何 bundle、版本、build、方法实现或固定窗口变化均须阻断清理，先重新审计再支持。
- `AxsCacheKeeperScanCursor` 持有打开的目录句柄；分片续采只在当前进程、同一个 cursor 生命周期中有效。进程终止、身份变化、配置/前后台撤销或读取错误时释放句柄，保存 partial 下界和明确终止原因；不得跨重启伪造 cursor 恢复。
- before/after complete 仅表示已证明候选集的测量完整。宿主没有提供完成回调时，submitted 不是清理完成证明，窗口观察不得写成因果删除量或物理可回收量。
- 既有 `scanDiagnostics.errors` 使用封闭阶段与错误域、错误码及计数，并有数量上限；历史投影沿用该规范并保留截断信息。
- 容量测量是只读，不扩张清理权限。完整重测不代表 APP 私有占用可清理，也不代表逻辑字节等于 APFS 可回收空间。

## 实现方案

采用一条统一证据链：

1. Gurd 范围解析器产生可审计的 scope proof，至少绑定固定宿主版本/实现身份、真实候选集合来源与规则、根身份、排除项和完整性状态。before/after 读取同一份经过验证的候选快照或由同一规则证明的全量候选；如果宿主未暴露候选清单，且无法独立复现完整清理谓词，则不提交，记录 scopeUnproven。不得以白名单子树代替。
2. Gurd 采样任务跨队列 slice 持有 cursor 和累计状态。只有 scope proof complete、before complete、门禁仍有效时才允许 host submission；after complete 前不报告完成观察。任何 partial 都保留观测条目数/逻辑字节/已分配字节下界、错误和终止原因。
3. UI 文案、状态摘要和导出都将限制能力限定至 SDWebImage，并将“已调用 API”“观察到写入尝试”“已阻止写入”分开表达。
4. 每个 scan recent history 条目携带限长的扫描失败投影；诊断汇总导出保留 unknown 与完整/截断的差异。
5. 容量终态绑定 epoch 到内存报告；新测量清除旧报告与绑定。导出前校验报告 epoch 与最新 terminal epoch 一致且本次汇总晚于该终态；取消、超时或局部失败原样标出，不宣称完整。

## 其他路径及取舍

- 仅增加 4 秒采样预算：拒绝。会延长后台任务且仍可能从头重扫，不能修正范围或续采问题。
- 采白名单子树：拒绝。它观测的是宿主保留候选，与真实清理范围相反或不等价。
- 只改文字、继续允许当前 Gurd 提交：拒绝。会把未证明的测量范围用于宿主资源动作。
- 导出时自动启动测量：拒绝。导出会产生长耗时只读工作，并使“用户确认后重测”的流程不可见；沿用显式重测、汇总、导出顺序并用 epoch 绑定强制一致性。
- 所选方案优先真实范围证明与 fail-closed；若当前宿主没有可证明的候选集接口，Gurd 宿主清理验收暂时保持阻塞，其他三项仍可独立交付。

## 验收条件

- 固定样本 `com.ss.iphone.ugc.Aweme 41.2.0 (412021)` 证明：对真实执行路径，范围解析结果与 `clearCacheExceptWhitelist:YES` 的候选规则完全一致；白名单、active/inactive 元数据、版本目录和全部跳过条件均有正反例。任何未识别条目、实现窗口或宿主版本身份变化均使 scope proof 不完整并阻止调用宿主清理。
- Gurd 运行时回归证明单次时间片耗尽后同一 cursor 从已保存位置继续、不重复计数或漏项；连续两个 operation 的 before/after 均 complete 且提交前复核 scope proof 与 lifecycle gate。增加身份变化、过期、配置撤销、异常、进程中断等 partial/不提交反例。
- SDWebImage 阳性对照执行确会产生新的磁盘写入；只有 `attempts>0` 才评价 prevent，prevent 下真实写入被拦时 `blocked>0`，关闭限制后 `allowed>0` 且恢复落盘。宿主 Gurd API 回执不计作 SDWebImage 写入证据。
- Swiftgram 跨轮导出含错误阶段、错误域/码、计数与截断；不含私密路径/错误文本；旧 schema 缺历史诊断时保持 unknown。
- 导出门禁覆盖：最新完整 epoch 可汇总导出；重测后未汇总、running、取消未确认、结果错 epoch、已汇总后又开始测量都禁止导出旧报告；终态含局部失败时导出失败明细，不补零。
- 保留明示排除项；不执行手机宿主清理来做设计或范围验证。真实设备验收必须先由离线固定版本证据证明范围，再进行授权的完整采样验收。

## 留给实现者决定

- 对固定宿主 `com.ss.iphone.ugc.Aweme 41.2.0 (412021)` 和现有运行时接口做静态/只读验证，确定是否存在可用的真实候选清单或完整谓词；不可证明时实现持久的 `scopeUnproven` 阻断记录，不猜测内部规则。固定身份依据当前 `AxsCacheKeeperGurdSource.m` 的宿主 metadata 和实现窗口核对，不得描述为 whole-binary hash。
- cursor 调度 slice 大小与每轮时间片由现有 scan cursor 负载和后台时间 API 决定，必须有公平性、可取消和句柄释放测试。
- 容量 epoch 与汇总时间字段沿用当前导出 schema 的兼容模式；新增字段采用可选版本化投影，旧报告不能被回填为新测量。
