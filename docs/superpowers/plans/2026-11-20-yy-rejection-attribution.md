# 抖音自然调用拒绝归因

本计划延续用户已授权的四 APP 定向核查；每个 SSH 只观察一个 APP。213808 轮已正常收尾，但 YY 两个入口 36 次调用全部 unresolved，原回执不能区分 selector、实际类、别名预算和返回路径失配。不能据此称没有写入，也不能猜测子类就是原因。

实现只修改临时观察器及其闭合 schema：保留两个固定 IMP、ABI、bundle/version/build/UUID、精确类准入。新增可选 callDetails，以每入口调用数、五种拒绝原因闭合 unresolved；对 selector 已匹配但实际类不符的调用，只读最多 16 个实际类的技术名字、至多 16 层继承关系及当前 selector 解析 IMP 是否仍为固定入口。名字仅接受有界 ASCII 类名；不读实例字段，不读业务 selector 参数，不主动调用业务方法。旧回执不补造原因。
