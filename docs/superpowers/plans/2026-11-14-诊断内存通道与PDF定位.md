# 诊断内存通道与 PDF 定位续作

> 执行时使用 subagent-driven-development 按任务实现，独立审查安全边界。本文细化已批准的重点 APP 方案，不改变清理授权。

**目标：** 在同一次诊断会话中定位一个系统解析目录里的 PDF 格式候选，避免重复 SSH 和全容器扫描。结果只在本机内存保留，手动导出时统一脱敏。

**架构：** 先验证现有 Settings 与 SpringBoard 两宿主的认证消息通道，再接入单目录读取、预算与会话展示。复用现有安装身份和诊断脱敏逻辑；现有持久深扫档案继续独立工作。

**技术栈：** 当前 Theos、SDK 16.5、iOS 16–17、RootHide、arm64/arm64e。

**规格：** [重点 APP 方案](2026-11-13-app-storage-remediation.md)第 2 项及[通用资源契约](../specs/2026-11-14-通用资源契约与新增应用.md)。下面的传输方式为开发侧根据接口证据作出的实现选择。

## 已核实的接口与限制

SDK 16.5 的 `mach/message.h` 提供 `mach_msg_audit_trailer_t`，libSystem 的 arm64/arm64e 链接表包含 `csops_audittoken`、`proc_pidpath_audittoken`、`bootstrap_register` 和 `bootstrap_look_up`。Apple XNU 的接口会校验 token 中的 PID 与进程版本，避免仅凭用户消息自报的 PID 或 bundle 判断身份。

- [XNU 16 codesign 声明](https://github.com/apple-oss-distributions/xnu/blob/xnu-8792.61.2/bsd/sys/codesign.h)和[实际身份查询实现](https://github.com/apple-oss-distributions/xnu/blob/xnu-8792.61.2/bsd/kern/kern_proc.c)。`CS_OPS_IDENTITY` 返回带 8 字节头的 blob，须校验网络序总长度和末尾 NUL。
- [audit 绑定的可执行路径接口](https://github.com/apple-oss-distributions/xnu/blob/xnu-8792.61.2/libsyscall/wrappers/libproc/libproc.h)及[实现](https://github.com/apple-oss-distributions/xnu/blob/xnu-8792.61.2/libsyscall/wrappers/libproc/libproc.c)，声明最低 iOS 14。
- [Mach 消息发送者 token 来源](https://github.com/apple-oss-distributions/xnu/blob/xnu-8792.61.2/osfmk/ipc/ipc_kmsg.c)及[bootstrap 声明](https://github.com/apple-oss-distributions/launchd/blob/main/liblaunch/bootstrap.h)。动态注册是旧接口，是否获准必须在两个真实宿主分别检查。

这是接口研究结果，尚未编译或验证宿主权限。缺失的私有头只能按上述精确声明作最小兼容适配；不导入 macOS 的 libbsm 头来假称公共 iOS 支持。iOS 16–17 token 访问集中适配并校验大小，不承诺未来 ABI。

## 任务 1：只有握手的认证通道

**文件：** 新增 `AxsCacheKeeperDiagnosticChannel.h/.m`，接入现有 SpringBoard 初始化和 `Prefs/DiagnosticsPage.m`，增加专用原生协议回归与 Makefile 源清单。

- [ ] 请求只包含协议版本、`hello`、随机请求 ID；响应只包含对应 ID、固定能力状态和错误阶段。此阶段不接收路径或读取 APP 内容。
- [ ] 首版使用固定长度 C 消息：版本 1、请求/响应类型、16 字节随机 ID、固定状态与错误阶段；请求和响应各最多 256 字节（不含内核 trailer），不接受额外字段。客户端单在途、共享 2 秒软期限、无自动重试；内核身份查询本身可能迟滞，期限不作硬实时承诺。
- [ ] 每次收发都请求并校验内核 audit trailer，固定消息上限，拒绝缺失/截断 trailer、复杂消息、额外描述符和异常大小；正确释放接收到的 Mach rights。
- [ ] 同一个 token 完成签名状态、精确 signing ID、实际 executable 路径核验，最后重验状态。预期 executable 从系统 URL 取得并核验；Settings 与 SpringBoard 双向认证。平台位和 bundle 字符串单独均不够。
- [ ] 两宿主先严格自检自身 token、候选 signing ID 与系统 executable；未证实的 ID 不放宽，也不从对端首次返回值学习。诊断仅报告可观测阶段；若服务不存在，Settings 只能报告 lookup/timeout，远端注册状态为 `notObserved`。
- [ ] 获取不到真实身份、API 被 sandbox 拒绝、服务名占用或 lookup 失败，返回具体阶段及系统错误；不降级为同 UID 放行，不扩大容器访问权限。
- [ ] 原生验证伪造 payload 身份、过期 token、同 UID 错误进程、坏消息、重复 ID 和超时。CI 分别验证 SDK 16.5 编译与 RootHide 双架构链接。
- [ ] 具体探针包可审查后取得设备部署授权，实测两个宿主 HELLO 往返及错误进程拒绝。普通 CLI 的权限不能替代宿主证据。

## 任务 2：单目录 PDF 引擎

**文件：** `AxsCacheKeeperInspection.h/.m`、必要的专属 FD 读取模块与 `tests/` 真实文件回归；旧深扫模式保持原语义。

- [ ] 明确 `pdfLocate` 模式；系统解析一个容器及选定相对目录，禁止调用全量 `scan_targets` 或进入硬链接孪生搜索。
- [ ] 系统容器根核验后，后代目录及文件全部通过持有的目录 FD 和逐级 `O_NOFOLLOW` 打开；完整容器相对路径先过敏感范围规则。普通文件与硬链接共用读取路径，最多读 4096 字节，只识别 `%PDF-`。
- [ ] 读取前后比较类型、device/inode、size、mtime/ctime，短读/变化/权限失败分别记录。最多 10000 枚举项、16 MiB 实际样本、5 秒单调时钟，先到者停止，每批最多 64 项；取消在枚举和读取前后检查。单次 I/O 延迟不作硬超时承诺。
- [ ] 报告保留最多 10 个按大小排列的候选，含路径数和截断、预算与覆盖状态；不保存正文、样本或内容哈希，不改变删除规则。
- [ ] 真实夹具覆盖无后缀 PDF、同 inode 多路径、小 PDF、同名非 PDF、敏感目录、替换/符号链接/特殊文件、11 个候选截断、三类预算、取消、相邻根未访问和零新增报告文件。

## 任务 3：同一内存会话与展示

**文件：** 认证通道、`Scanner.m` 的单根解析入口、`AxsCacheKeeperDiagnostics.h/.m`、`Prefs/DiagnosticsPage.m` 及相应测试。

- [ ] 每个会话绑定双方完整 audit 身份、服务实例和 generation，每条消息重新核验。初版仅一个活动任务，忙时明确拒绝，不排无限队列。
- [ ] 请求只接受 bundle、单个数据容器的相对目录及固定模式，拒绝绝对路径、任意根数组和预算扩大。开始读取前复核安装与目录身份。
- [ ] 离页、连接释放、客户端退出、服务重启或租约到期取消并释放 FD/候选；晚响应不得恢复旧会话。接收/取消与扫描队列分开。
- [ ] 内存候选通过同一脱敏器并入手动导出 JSON，禁止先序列化原始路径再拼接。Filza 入口重新核验当前安装和相对路径，只报告投递结果。
- [ ] 实测单目录只读访问权限，再开放定位入口；不能以 HELLO 成功证明目录访问已经获准。

## 任务 4：交付与后续资源动作

- [ ] 备份、原生回归、独立审查、普通提交推送、对应 SHA 的 Actions、四资产与 deb 核验；文档分别记录源码、发布包和设备验收状态。
- [ ] 定位成功后继续百度资源 ID/下载管理器与 Swiftgram 对象上下文研究。格式识别和候选路径不授权删除；可恢复集合及真实回收/恢复回执未取得前保留资源。

当前进度：接口研究完成，任务 1 的 HELLO 源码、SpringBoard/诊断接线、状态白名单与原生回归已落盘。独立审查发现的发送失败和部分接收失败 Mach 权利释放遗漏已修复；测试区分真实发送超时与使用真实已交付权利的错误码注入。诊断额外记录本地/已认证对端错误来源，真实后台公共接口返回也会经过报告契约回归。Windows 无法执行原生测试，当前等待对应提交的 macOS、SDK 16.5 双架构和设备宿主验证，以上验收项尚未全部完成。

任务 2–4 继续按依赖推进；当前设备基础清单继续复用，不重新盘点全 APP。HELLO 成功只证明认证通道，不能代替 APP 容器只读权限或资源可恢复性验证。
