# 宿主证据与大目录续扫整组实现计划

> 面向 AI 代理：使用 subagent-driven-development 按任务实现、审查；按用户要求全部完成后统一提交推送，不逐任务发布。

**目标：** 解决计量反复超时而无法继续、宿主新旧回执无法定位、其他 APP 能力缺口难以统一判断的问题。

**架构：** 只读计量使用有界分片和同一次任务内的游标；宿主提供独立的只读证据通道，诊断从原始记录派生能力摘要。继续使用现有清理、授权、容器发现与 SDK 契约。

**技术栈：** Objective-C/Logos、Foundation/UIKit、Darwin notify、Theos SDK 16.5、RootHide、Python 原生测试编排。

**规格依据：** 用户 2026-11-17 指令、项目 AGENTS.md、[三阶段诊断](../../2026-11-17-166.2三阶段诊断复核.md)及[通用资源契约](../specs/2026-11-14-通用资源契约与新增应用.md)。

## 范围、不变量及验收

- 全部 APP 复用统一实现；汽水音乐、抖音是计量验收样本；Swiftgram、百度是宿主证据验收样本。风起云涌、微信不列本轮整改或真机验收目标，不改其配置。
- 已有 130 条新扫描仅 4 条明确计量超时；用户排除其中 2 条。其余扫描完成不能外推为已安全适配私有资源。16 份 154.1 SDK 回执不是新版证据。
- 只读探测不得刷新缓存策略、申请新授权、清理资源或改变配置。新通道与旧有副作用的网络探测分开；notify 是观察信号，不宣称认证通道。
- 字节数仍是逻辑计量；部分结果不得标完整，不累加不同代际、不同容器或重复扫描。取消、重启、保存失败及无法继续必须有明确状态。
- 新旧版本、缺失、无响应、不可读、无匹配 SDK、契约拒绝、调用完成、限制/恢复实际验证分别表示；回执存在不等于治理成功。
- 不改包身份、SDK、架构、权限或 RootHide 路径规则；不改未知资源删除授权。
- 旧文件先备份 BK；临时证据仅 tmp；用户 AGENTS.md 不提交。全部本地可执行检查和独立审查后统一推送，再跟进完整 Actions 和验包。

## 审查重点

1. 大目录分片交接必须不重复/漏记，单步有界、资源释放；不能因 UI 收到部分回执而误判完成。
2. 新请求、取消、容器/根身份改变和保存失败不能发布旧结果为新任务成功；批量任务不得被一个大目录长期占用。
3. 只读宿主检查不调用原 refresh_network 或 libSandy 授权；丢失、旧 nonce、畸形版本或串扰不得当新响应。
4. 当前面板版本与宿主版本独立比较，只有匹配证据才标当前；历史 APP/SDK 状态不得伪装当前运行状态。
5. 报告不得引入原始路径、内容、标识符等隐私泄漏；诊断汇总继续不触发扫描或清理。
