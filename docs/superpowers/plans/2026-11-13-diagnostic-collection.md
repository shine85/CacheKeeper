# 已配置应用诊断采集与搜索修复

目标：用户一次导出所有已配置 APP 的诊断记录，减少逐页截图；继续修复首页搜索输入。

范围由本次请求确定：当前配置的 APP、清理回执、目录与深度检测、文件属性和硬链接关系。采用现有 Objective-C / Foundation / UIKit，不改变清理规则，不复制第三方清理器。

## 实现决定

- `AxsCacheKeeperDiagnostics.h/.m`：配置集合、串行请求状态机、白名单报告、路径匿名化。只读已有诊断；补采复用现有 `request.plist` / `inspectionRequest.plist`，后台继续由 Scanner 执行。
- `Prefs/DiagnosticsPage.h/.m`：开始补采、停止、导出已有记录；展示每个 APP 的阶段和失败。分享单个 UTF-8 JSON 文件，用户自行发送；无自动上传。
- `Prefs/Settings.m`：诊断入口；自有根视图及安全区约束，搜索与列表不重叠，横滑手势只作用于列表。
- `tests/diagnostics_tests.m` 与原生 runner：真实临时 plist 验证集合、脱敏、旧 token、取消、缺失/损坏、超时及只读性。

## 不变量

1. 范围取 `appEnabled.plist` 和 `directories.plist` 已配置键的并集，包含已关闭配置，不取当前分类/搜索或全部安装应用。
2. 一次只提交一个补采请求；只接受同 token 的结果；不覆盖其他页面未完成请求。停止只取消本会话的深度检测，不触发删除。
3. 报告区分缺失、损坏、历史记录、本次结束/部分/停止；保留时间戳与所有覆盖/截断标记。不把扫描完成当作清理完成。
4. 输出不包含容器绝对路径、账号号段、私人文件名、原始错误文本、文件头字节或文件内容；保留已知技术目录、扩展名、大小、类型、计数及匿名路径关联。别名映射仅存在本次导出内存中。
5. 系统版本/架构/包版本可导出；不读取设备名、序列号、通讯录或账号数据库。导出文件仅在本地分享临时目录，分享结束清理该文件。
6. 补采不修改配置。目录扫描沿用现有重新核验调度行为；不会绕过清理条件、用户排除、硬链接和数据保护。
