# Gurd 宿主缓存清理接入

本文件细化用户已批准的全 APP 方案任务 4，不改变最终验收目标。200.1 是通用修复阶段成果，不能替代私有主体治理。

## 已核实现与选择

当前抖音 41.2.0/build412021、AwemeCore UUID `cc3b646814e43c7fa8708f1eb5f4adeb` 的 `IESGurdKit clearCacheExceptWhitelist:` 为 `v20@0:8B16`。传 YES 后委托 `IESGurdFileBusinessManager clearCache:YES`，复制宿主白名单并遍历当前资源元数据；小程序、游戏容器、白名单通道、锁定通道保留，删除交给宿主通道队列与索引管理。该入口没有清理完成回调，返回仅表示调用返回，不能写成 apiCompleted。

过期入口是另一条目标列表政策：目标组／通道命中后按最近访问和过期天数判定，存在 300 秒提前返回。因此不把过期入口与白名单入口拼成未经证明的清理接口。本次选择已核白名单入口清存量；不裸删 gurd_cache、不更改宿主缓存策略、不对 Gurd 实施写锁。后续同实现族可复用，未核版本保持不支持。

## 不变量

1. APP 总开关、有效配置、当前安装、宿主实现与实际缓存根身份全部有效才提交；三模式均可清存量，Gurd 限写明确不支持。
2. 自动发现开启或用户明确选择该私有根才覆盖该范围。与实际根有任意重叠的排除项使整个宿主动作跳过，不能调用全根 API 再声称排除生效。
3. 不采集业务键值；模块／选择子／类型属于技术证据，资源路径仅在内存使用。实际根从已核宿主 getter 获取并与系统主容器核对，不能用拼接猜出的目录授予权限。
4. 后台准备、平台任务、配置变化采用代次防迟回调；准备后及 selector 调用前复核。提交前撤销能取消；提交后的宿主异步任务不能伪报已取消。
5. before／after 只计同根普通文件逻辑与已分配字节。权限、链接、身份变化、预算耗尽明确部分或失败；变化仅称同范围观测减少，不称独占物理回收或宿主完成。
6. 同一次后台事件只提交一次，等待宿主操作窗口结束后不因零变化反复调用。下一次前后台与新配置事件才重新评估。

## 实施文件与测试

- `AxsCacheKeeperGurdSource.h/.m`：固定实现合同、类／方法／UUID／代码指纹校验和只经核验的宿主调用。
- `AxsCacheKeeperGurdCache.h/.m`：授权、后台生命周期、同根效果观测、提交后状态与脱敏回执；宿主边界与采样器分别注入，产品默认使用实际实现。
- `AxsCacheKeeperGurdRuntime.m`：接现有配置来源、RootHide 共享回执、UIKit后台任务与生命周期；不改变已关闭 APP。
- `tests/gurd_cache_tests.m` 与 runner：真实文件前后观察、范围保留、撤销、迟准备、同步过期、submitted 非 completion、恢复、旧回执及严格字段边界。合同失配不能调用任何 getter／清理。
- 最后集中接 `Cleaner.m`、Makefile、Diagnostics／StorageInventory，真实源代码审查、原生完整回归、Theos／deb 与授权真机实际动作才完成交付。

## 真实验证边界

引擎原生测试可以证明自身状态、权限和文件观测；外部宿主测试适配器不证明当前 Gurd 行为。当前宿主必须另外验证真实入口准入、清后目标减少、保留项可用、重新访问资源恢复。手机资源清理须在代码与范围具体可审后依项目规则取得明确确认，不能把此前只读诊断授权扩为删除授权。
