# 百度启动阻塞修复计划

**目标：** 修复插件自身会把回执写盘、网络缓存调用阻塞传到宿主前台的两条调用链，同时保持清理授权、限制写入和关闭恢复的现有语义。

**依据：** 用户反馈安装 228.1 后打开百度卡住。`1120-03.json` 在图片采集的 clean 阶段没有提交 SDK 清理，不能归因于清理动作；报告没有线程栈，以下是源码可复现的阻塞缺陷，不能代替目标手机根因认定。

## 设计与不变量

- `AxsCacheKeeperImageCache.m` 当前在引擎锁内调用 observer，生产 observer 同步获取 Runtime 上下文锁并写回执。新增仅用于发布的串行锁，顺序为发布锁 → 引擎锁构造快照 → 释放引擎锁 → 同步 observer。主线程生命周期与读取回执只获取引擎锁；保留回执顺序、同步写入结果及失败时拒绝清理的规则。
- `AxsCacheKeeperNetworkCache.m` 的全局锁仅保护容量请求和策略状态。原系统 getter/setter 在锁外调用，按请求与策略版本重新检查，旧调用晚返回时应用最新请求；保留初始化帧、类簇、内存缓存及来源未知时恢复未验证的语义。
- 不使用异步丢弃回执、超时后伪造成功、关闭全部限制或增加主体目录删除范围来掩盖故障。
- 本轮不重复手机采集，不连接设备，不绕过此前被拒绝的私有运行时取证；也不以本轮可靠性修复宣称五 APP 私有主体适配完成。

## 实施与验收

- [ ] 在现有 Runtime 行为测试中构造上下文锁阻塞，证明旧引擎使前台生命周期等待；修后前台能完成撤销及读回执，原 observer 仍实际落盘。
- [ ] 验证并发回执按顺序写入，较旧回执不能覆盖新状态。
- [ ] 用真实 Foundation 网络缓存和透明测试调用层复现跨线程 setter/getter 的全局锁阻塞；验证修复后另一实例能完成调用。
- [ ] 验证旧请求晚返回、策略切换、类簇初始化、关闭恢复及真实内存响应读写。
- [ ] 本地对象编译及定向编排检查、独立复核后整组提交，运行同一 SHA 的原生 RED/GREEN、SDK 行为回归、Theos 构建及 deb 验包；Windows 不冒充 Foundation/UIKit 行为环境。

**最终目标边界：** Gurd 真实清理范围及全部写入保护、QQ/京东/百度主体/Swiftgram 私有适配仍需其资源与执行契约。本轮直接推进宿主可用性和现有清理/限写的可靠性，未补齐的主体能力如实保留为未完成。

## 开发侧实施结果

两处产品修改已完成。网络调用在登记请求的同一锁区预占未完成计数，原生写入完成序号保护验读结果；发生并发覆盖时合并一次最新意图补偿，失败版本禁止自动重试，后续明确配置可以恢复。稳定无竞争的调用保持同步，待完成调用存在时不提前报告已恢复。

新增图片阻塞与发布顺序两个场景、网络十五个场景，分别固定 228.1 的旧源码作为精确失败对照。独立审查已核对全部图片发布调用与网络晚写、验读、异常交错。七个 iOS arm64 对象编译退出 0；Windows 无 macOS Foundation，真实行为结果必须取同提交云端运行，不能用对象编译或源码审查替代。新报告不足以确认手机实际阻塞栈，目标机百度启动是否恢复仍须后续确认。

新文件，无旧版本可备份；既有实现与测试修改前保存于本轮 `BK/`。

## 首轮真实回归与补修

Actions 46139713948 / `5ebc572` 实跑：图片旧版阻塞精确反例、新版前台不等待及发布顺序通过；网络两个旧版锁阻塞反例和十四个并发场景通过。完整原生组同时发现初始化抛异常后内部状态遗留，以及磁盘恢复行为反例仍引用重构前的源码位置；该构建失败且未交付。

补修将初始化内部状态放在根初始化帧借用的临时对象中，成功返回后发布；明确应用请求仍立即保留。异常和 nil 返回不污染全局，已发布对象及成功的独立嵌套对象继续保留；未完成初始化不得自动补偿调用。补充失败接收者保活、跨线程零/非零请求及已发布对象仍在初始化时的未完成调用测试。

图片发布锁解耦后，旧主队列通知可能看到未来尚未写盘的内存快照，提前释放后台时间。Runtime 改为传递已经完成 observer 的快照，协调器的通知与调度完成路径共用该视图；新增阻住终态写盘、处理旧通知、放行后实际落盘并恰好结束一次的行为测试和精确失败对照。该测试使用既有可控 SDK ABI 夹具，不冒充目标 APP 或真实 SDK 删除验证。

补修后六个 iOS 对象编译退出 0、无诊断，17 + 4 项编排及 14 文件 XCTest 宏检查通过；上述新行为仍待下一同提交 macOS 实跑。原失败证据独立保存在本地 `packages/验收证据/运行46139713948`。
