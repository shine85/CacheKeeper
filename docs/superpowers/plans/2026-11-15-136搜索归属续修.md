# 136.1 搜索归属续修计划

目标：修复可见导航栏与包装控制器导航项不一致时的紧凑布局遗漏，补齐能区分实际宿主状态的诊断，并据新报告解释存储大户未回收的原因。

执行：沿用已授权续修、普通提交推送与 Actions 交付；采用 subagent-driven-development 完成实现和独立审查。保留当前 main 与用户修改，不创建新分支。

事实：最新报告为 136.1 / iOS 16.2。didAppear 时可见祖先栏已经高 91pt，1 秒后只是 interaction 从 false 变 true，搜索随避让下移 47pt；不能再把它描述为这段时间内导航栏重新变高。报告没有记录导航候选判定，具体失配条件尚未得到真机证明。

## 约束

- 沿完整父控制器链核实可见分支，每层 navigation.topViewController 必须等于对应直接 child；失配立即停止向外认领。
- 在已确认分支中使用 navigationBar 实际 topItem；若不等于 child.navigationItem，仅在本页 didAppear 且导航转场结束后允许认领。不能修改旧页面或无关覆盖栏。
- 保留初始模式和 prefersLargeTitles；宿主显式 Always 与离页恢复保持原语义。强制布局仅作用于仍有效且模式为 Never 的现有认领。
- 几何避让按可见栏实际区域计算；祖先栏暂时禁用交互不能导致搜索先与其重叠、恢复交互后再跳动。不硬编码减去 47pt。
- 诊断仅增加有限布尔/枚举状态；不输出类名、标题、地址、搜索内容或原始对象。生成与导出共用校验。
- SDK16.5、iOS16–17、RootHide、包身份与路径规则不变。修改已有文件先备份到 BK；测试宿主不得进入 deb。
