# 构建失败集中整改

## 采用的分析与纠正

依据用户提供的 2026-11-16 分析、#155–#164 已读取的失败日志及本地提交差异集中整改。上一轮将未经实跑的推测直接作为根因、逐点推送，以及删减预算覆盖和放宽单项期限，均不足以证明问题解决。

报告中的时间夹具、格式警告、同名类替身和首失败中断判断可采纳；以下事实须区分：

- 执行环境是 Windows；Foundation、UIKit、Theos 无法在本地实跑。
- #159 的新增诊断调用了不存在的 NSDictionary selector，实际发生 Objective-C 运行异常。未进入 Theos 编译不等于没有测试程序编译或运行错误。
- #157/#158 的写入失败没有定位到具体写入点；创建根目录不是已证实根因，因为测试本就递归创建 Status。不能将该假设写成修复事实。
- #160/#161 的外层超时只证明整组未及时结束，不能直接认定 16384 行资源报告是瓶颈。
- 包号由工作流运行号生成，不能承诺某次运行发布固定的 155.1；失败运行不交付包。

## 已实施的集中变更

1. **日期夹具与格式检查。** 旧 XML plist 路径使用整秒观察时间，当前 binary plist 路径保留 `.25` 小数秒；两者均经过保存、生产 Diagnostics、JSON 回读后精确比较，仍检查源文件不被改写。移除错误的 `fprintf("%@")`；原生与 UIKit 测试编译将格式警告视为错误。
2. **恢复覆盖与修复关联表退化。** 恢复 16384 行保存报告、精确省略数、未授权根、只读文件检查和 JSON 往返。容器关联键由固定长度 NSArray 改为经过验证的 `owner:identifier` 字符串；标识允许字符不含冒号，故可以唯一还原，扩展仍按全局 plugin identity 撤销矛盾。计数、URL 去重和预算不变，新增歧义拼接与冲突后不得重新准入的行为用例。原生程序期限恢复为 60 秒，并增加单调时钟阶段计时。
3. **去除同名系统类。** 两个角色均通过测试 wrapper 替换类查找边界，返回带项目命名空间的 workspace 替身。旧源码先验证固定 SHA256，再原样导入；取消生产文件中的测试专用注册表宏。RED 保留精确退出码和失败文本，不再过滤同名类警告。
4. **一次收齐独立失败。** 原生入口运行 30 个独立组，各自保留日志、耗时、退出码和汇总 JSON。一个组失败不阻断其他组；同组编译失败仍阻断其二进制执行。失败、超时、缺环境分开，任一失败不能发布。
5. **独立云端验证入口。** 原生测试独立成 job；手动 `native_only` 只运行已上传 ref 的原生测试。默认完整流程必须原生通过后才能运行 UIKit、RootHide 编译和发布。此入口不能执行本地未上传修改，也不代表已取得另一台 Mac。

## 性能证据边界

Apple 公开 CFArray/NSArray 实现的 hash 返回数组元素个数。旧代码使用大量两元素数组键，在同一 group 表里形成集中冲突；收尾还按同键回查。字符串键消除了该结构性风险，但此前 100–178 秒的实际耗时是否全部由此产生，仍需新 macOS 阶段计时验证。保留完整夹具和 60 秒门，不能以提高超时替代性能证明。

## 本地验证与剩余验收

Windows 可运行的批处理行为测试验证首失败继续、编译依赖、超时、缺环境、退出码与日志；原生默认入口须逐组明确 UNAVAILABLE。Python AST、固定源 hash、diff 与测试入口静态核对不计为 Foundation 或 SDK 成功。

集中复核后统一推送，读取同提交所有原生组结果；遇到失败先收齐整组日志，再集中修复相关问题。完整原生、三版真实图片 SDK、UIKit、SDK16.5 RootHide、deb 和发布必须分别有成功证据。

这轮主要恢复开发侧验证可信度。百度实际来源与安装时间视图、Swiftgram 新深检、标准缓存的实际清理/限制/关闭恢复、全 APP 私有资源契约、物理效果归因和 iOS17 真机验收仍是独立未完成项。成功验包前不安排手机测试。

## #165 实际结果与关联修复

同提交14be6e3的运行43920767130完整执行30组，24通过、6失败；UIKit/RootHide/发布被正确阻断。时间导出、清单RED/GREEN、安装身份及源码指纹组实际通过。清单套件总耗时20.834秒，保存预算/JSON5.128秒、直接预算2.146秒、4097登记2.131秒、16385组关联0.754秒，完整预算保留且60秒门通过。该结果验证修复后的运行表现，不将跨runner总耗时差精确归因。

6组失败归并为4个机制：操作历史的4处C逻辑表达式装箱为整数而非CFBoolean（影响3组）；operability标记错误复用允许数字0/1的配置校验器；Unicode变异只切ASCII编码不能保证制造预期opaque错误；平台规则复用配置路径校验时误拒绝合法POSIX反斜杠文件名。集中修复分别显式BOOL装箱、共用严格operability类型验证、明确注入非ASCII转opaque、按文件父目录决定平台范围并校验末级名字。原准入、排除、保护、身份与期限保持，新增固定#165四条精确RED与边界负例，等待同提交完整复验。
