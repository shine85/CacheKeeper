## 新版本集中手机验收

1. 用成功交付的 deb 升级，按包管理器提示加载，完全退出设置再打开；确认完整版本，保留现有配置。
2. 对一个已开启、缓存可重新获取的 APP，正常使用后退出，等待合格清理终态，记下最近一轮和最近实际清理的时间/计数。再做一次空轮或仅刷新，最近有效删除历史应保留，空轮如实为零。检测目录本身只更新快照，不触发删除。
3. 切三模式，关闭再打开，检查旧轮结束时间、模式、版本、失败与覆盖状态没有随当前配置变化；关闭或无选定目录时历史及 action 状态仍显示。已适配图片 SDK 需要宿主存活，另按“正常使用→切后台保留进程→查看同次回执”核对，不能先划掉 APP。
4. 完成一次检测，查看 Swiftgram 三类、百度首拒绝与各 APP 实际回执；失败和未覆盖应保留，不能显示为已清空。核对原搜索/清除/取消/返回入口，以及登录、草稿、消息和离线原件。
5. 最后一次“汇总已保存诊断→导出报告”，保存“新版本集中验收.json”，附操作顺序、各阶段模式和可见异常。百度出现新首拒绝时另导出“百度首次运行后.json”。崩溃仅附同时间脱敏日志，不上传 APP 内容、数据库或凭据。无需 SSH。

标准清理、图片 SDK、独立网络及网页回收必须分别看实际动作与恢复证据，不能仅凭开关、方法存在或容量置零判断生效。详细基础流程见 `docs/2026-11-13-真机验收.md`；四 APP 未闭合契约不要求用户试清私有目录。
