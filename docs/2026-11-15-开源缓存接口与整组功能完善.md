# 开源缓存接口与整组功能完善

日期：2026-11-15。开发基线 `49e0416`。本文件是本轮实现与验收计划，勾选完成必须有实际执行证据；不表示新增能力已经发布或真机通过。

## 用户目标与交付节奏

目标是对已开启 APP 的可回收缓存清存量、减少新增写盘，并在关闭时恢复原行为；同时保留必要业务数据。先从完整真机诊断、现有代码与同类开源实现得出整组方案，完成实现、真实测试和整体复核后统一推送。云端成功与下载验包后再安排一次集中真机验收。复用已完成的 304 注册条目本地技术档案，不重连 SSH。

## 本轮集中实现

1. 搜索：147.1 真机已确认输入能进入编辑，但用户仍报告上下跳。祖先栏在 44/91 pt 间变化，保存的 16 个事件输入顶均为 97.67 pt，不能将未保存的中间位移说成已采到。修复方向是停止每秒强制重排与 sizeToFit，并让已认领紧凑栏的可透传空白扩展不再触发搜索避让；未知栏、真实控件、显式大标题与离页恢复保留。新增跨布局、跨 tick 和连续真实输入稳定性回归，不以瞬时点击成功代替稳定性。
2. 图片缓存：以 SDWebImage 已确认的 Objective-C 实现族作为首个 SDK 适配器；从实际初始化返回对象观察，使用其正式缓存接口；禁止凭类名新建默认缓存或扫描任意对象。仅处理 APP 当前已授权标准缓存根内部的真实缓存目录。通过同一配置来源复用总开关、模式、手动关闭目录和排除；未知、自定义后端、并发队列配置、共享目录及不能证明授权的范围明确保留。
3. 减少写盘：自动/限制模式在已验证实际 SDDiskCache 写入入口决定是否放行，内存缓存保留；只清理模式和关闭后恢复原调用。不得使用全目录 chmod、阻断任意文件写入，或将所有 SDK 的容量 0 当作统一禁止语义。
4. 清存量：按真实 owner 的串行 IO 路径执行，排队与执行时复核最新授权、安装和对象代际。回调不含错误时只能记 API 完成，不伪造删除数或释放字节；超时、关闭、路径变化和多 owner 均有明确状态。不得因为一个方法名存在就放开整个 SDK 或 APP。
5. 安装预检：把根目录、Info、主程序、版本和复核的具体阶段与实时 errno 加入固定字段，保留现有拒绝边界和错误码。贯通真实 WebKit 回执与导出，避免下一次报告仍只得到合并原因，继续来回补采。
6. 页面与诊断：清楚区分标准网络、网页和已适配图片缓存的能力、执行结果与恢复状态；不把“开关已开”当成“已运行”，不增加第二配置事实源。所有未知或未观察状态可诊断。
7. 目录访问：通用访问助手对中间祖先仅请求 O_SEARCH，末级仍要求可枚举；安装根仅用于 fstat/openat，按同一最小权限原则独立核验。不修改用户目录权限，不放开末级链接。真实权限测试覆盖可遍历但不可读的祖先、不可读末级、不可遍历祖先，以及文件描述符标志。

两版固定 SDK 源码复核发现三个关联点，集中处理后再复验：

- 标准 [SDMemoryCache 初始化](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDMemoryCache.m#L56) 对共用配置添加 KVO，配置实际运行时类因此派生。精确 `object_getClass(config)` 检查误拒正常实例；修复应认可受限的系统 KVO 派生，同时保留实际对象身份及关键 getter 实现校验，不能泛化放行自定义配置。
- [SDImageCache 初始化顺序](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDImageCache.m#L130) 是先建 IO 队列、再初始化可配置的内存后端。自定义后端可能改写配置，让返回后的属性不能证明既有队列串行；须限定已核验的标准内存后端和实际实例，并验证这种拒绝场景，不删除内存缓存。
- 5.15.5 的磁盘目录首次写入时才创建，与 5.21.7 初始化建目录不同。测试前置必须使用真实 SDK 建立缓存，产品只能在真实写入后重新核验未建立身份的目录；不能由插件伪造目录或重新认可已发生身份变化的旧目录。

运行器原本在任一套件失败后立即跳过后续所有独立套件，遗漏了同轮搜索结果。本轮改为共享构建与来源校验成功后，逐组记录 WebKit、两个 SDK 和搜索/XCUI 的结果，再以非零退出汇总失败；第二 SDK 的生成、重建或来源校验失败时仍禁止执行其测试。Windows 已实际通过 20 个编排场景，覆盖失败继续、超时、错误/混合来源结构、构建阻断和附件导出，只有编排得到验证，尚不代表 UIKit 或 SDK 行为通过。

集中续修包括受限 KVO 准入、初始化前原始配置快照、标准内存/磁盘后端与关键方法身份校验、真实首次写入后的目录核验及限制重复刷新。原 19 条 SDK 行为用例全部保留，新增 4 条覆盖标准 KVO、自定义后端伪装并发队列、首次写入建立目录，以及未授权/重叠实例持续写盘时的配置读取次数，共 23 条。已从既有三个 APP 的原始分片重放校验全部 9 个新增方法签名；解析脚本和结果留在本地技术资料，未重新连接设备。以上仍是进入完整云端复验的候选，两个 SDK 的真实执行、搜索/XCUI 与打包结果必须以随后同一提交的 Actions 为准。
