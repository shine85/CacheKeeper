# 版本兼容与资源接口依据

## 产品原则

用户要求 APP 更新后仍可持续工作，而不是每升级一次就必须等插件硬编码新版本。适配应根据实际能力与数据契约判断；版本号、构建号用于定位回归、记录已测样本和排除已知不兼容实现，不作为所有规则永久按等号放行的唯一依据。

同版本安装包能帮助复现当前问题，但不是开始研究的必要条件。开发侧先自行查找作者公开安装包、官方源码和可获得版本；没有同版本包时继续分析公开版本，明确未完成安装构建映射，不把材料寻找全部交给用户。

用户最新范围是仅对当前设备全部 APP 做一次检查，未来新增或升级由统一能力与资源契约增量流程自动处理，无需用户人工查资料。共享安装提供器、安装身份变更撤销旧作业和诊断安装并集已写入本轮源码，待 CI；私有资源能力与恢复集合仍未闭合。不能用“取得应用清单”或每个版本追加一个硬编码条件替代长期兼容能力。新增/升级使旧任务失效后，应只重验变化相关的能力、资源契约及保留集合；已证明兼容的范围复用，未知范围保留并记录具体缺口。

## 分层兼容

| 规则类型 | 生效依据 | 更新后的处理 |
|---|---|---|
| 标准缓存及必要保留 | 系统容器、标准用途、用户排除及精确保留范围 | 不因 APP 版本改变停用通用规则；继续重新核对文件身份、进程与配置 |
| 稳定格式/路径资源 | 已验证的资源结构、格式身份、依赖与恢复条件 | 同一契约的多版本可使用同一规则；未知结构只暂停该范围，不能只见扩展名或文件名就放行 |
| APP 自身清理接口 | 真实对象上下文、方法/符号及调用约定、清理语义和保留集合 | 在独立证据证明兼容的实现族中复用；缺失、签名或语义变化时撤销该动作，不改用更宽的删除 |
| 当前试验规则 | 证据覆盖较窄，尚无充分的多版本兼容证明 | 暂时保留小范围版本限制，清楚标注限制；不是最终产品设计 |

仅有方法名相同、`respondsToSelector:` 成功或语义版本主号相同，均不足以证明清理语义兼容。Swift 的函数源码签名相同也不自动等于二进制地址、ABI 或可用的 Objective-C selector 相同。不能把版本条件简单改为“全部版本”并称为已实现兼容。

APP 版本变化仍使旧清理任务失效、重新获取证据；新任务可根据相同的兼容契约继续工作。保留规则不随删除规则失配而撤销。设备验证记录按版本保存，不把全部未来版本标成已验证。

## Swiftgram 13.0 与 13.2 已核实的源码

2026-11-14 从作者仓库 `Swiftgram/Telegram-iOS` 自行取得：

| 分支 | 固定提交 |
|---|---|
| release/13.0 | `ba54d9823d413f9816e5eee2724da77d5079f4cf` |
| release/13.2 | `55b4eb60ee29626eadd89b3c0134a14ae189df0b` |

- 两者 `submodules/Postbox/Sources/MediaBox.swift` 内容完全一致，SHA256 均为 `67fec306a9828dca4015bc20ee9bfa26eeb0b19efa5506fa34df5924ec24e27b`。这提供一个跨产品版本稳定实现的样本，不代表未来版本永远不变。
- `TelegramEngineResources.swift` 有其他变化，但三个 `clearStorage` 重载、`clearCachedMediaResources` 和 `removeCachedResources(ids:force:notify:)` 的声明保持一致。
- `MediaBox.removeCachedResources` 在资源数据队列执行；`force=false` 时检查仍在使用和被保留的资源上下文，按资源 ID 处理完整文件、partial 与 meta。不能在插件外面照搬这些 unlink，因为外部路径扫描不具备相同上下文。
- 该方法的进度/完成信号没有逐项检查 unlink 成功；不能将回调到达直接登记为全部字节已释放。接入后仍须验证目标资源状态和实际成功项。
- `TelegramEngine.Resources` 持有私有 `Account` 实例；这些源码方法没有提供可直接调用的 Objective-C 桥接声明。当前还缺安装二进制中真实可达的桥接、有效账号上下文和可恢复资源集合，因此尚未启用自动媒体清理。

源码与对比文件只保留在本地 `packages/research/Swiftgram-13.0-ba54d98/` 和 `packages/research/Swiftgram-13.2-55b4eb6/`，包含固定提交与文件哈希。没有把第三方源码复制进插件。

## 下载调查的实际边界

- Swiftgram 作者的 GitHub Releases 列表为空，官网与公开链接频道指向 App Store / TestFlight；此次没有找到作者公开的 13.0 IPA 附件。找到 `release/13.0` 分支后已继续源码分析，不再将“没有13.0标签”误当“没有13.0源码”。
- Apple 公共元数据当次返回：百度网盘 13.37.5、Swiftgram 13.2。元数据接口本身不返回可直接下载的 IPA；当前环境没有已登录的 App Store 下载客户端。未索取账号或密码。
- 没有同版本包并不阻止继续研究；能否完成某个二进制桥接，要以实际取得的材料为准。当前未取得两款 APP 的 IPA，不能声称已下载或已验证安装构建接口。

## 2026-11-14 安装构建的静态补充证据

从当前设备只读取得 Swiftgram 13.0 / build 319 的 PostboxFramework，文件大小 4,481,696 字节、SHA256 `7602d9b668bef8088e115e72c52bfce17b6ff9f1afe17d1336688d6ec7e4ce01`。该 framework 的加密标志为关闭，未进行 IPA 解密。

常规符号表共 585 项，未命中 MediaBox；进一步解析 dyld export trie 共 5,430 个导出，实际存在 `MediaBox.keepResource`、`removeCachedResources` 和 `removeCachedResourcesWithResult` 的 Swift 修饰符号。这补齐了安装构建确实含相关方法的静态依据，不能据此声称已有 Objective-C 桥接、有效对象上下文或恢复集合。两种移除方法的回调都不能未经核验作为逐资源删除回执。

证据和逐 APP 完整列表仅保留在本地忽略的 `packages/`，不公开用户完整安装清单。解析来自本地 Mach-O 工具，不冒称 REA 反编译或运行时调用结果。
