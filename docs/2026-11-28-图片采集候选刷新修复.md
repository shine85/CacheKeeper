# 图片采集候选刷新修复

新增文件，无旧版本可备份。依据用户 2026-11-28 操作复现和截图：一次性向导、五 APP 宿主预检、全容器容量后，进入图片采集页点击开始，显示无候选，下一阶段等按钮灰色。开始和跳过仍可点击。截图可见过期回执和大量关闭 APP 原因；没有今日新报告，昨日 220 报告不能充当今日准入证据。

## 根因与不变量

`availableModules` 复用执行准入的 300 秒限制，只返回可立即执行的回执；回执过期早于 eligible 判断，可能掩盖无合格 SDK。页面 idle 轮询不重新读取所选 APP，用户无法选择待刷新目标；全部关闭 APP 的原始错误又淹没了可操作项。

- 发现/准备与执行分离：合法、原设置已启用、历史有合格实例的回执可以作为待刷新候选；它不是当前执行授权。未知、无回执、关闭、无合格实例不得冒充可适配。
- 选择只保存准备记录，不发租约、不改配置、不启动 APP。用户自行打开选中 APP 后，复用引擎已有前台刷新和持久回执。
- 返回前台及有限定时重检只读所选 APP，要求取得比准备时更新的回执；仍须当前新鲜、合格、无 pending。实际开始再次核验并绑定当前进程身份；既有范围/安装/租期/ACK/清理门不变。
- 同一图片会话和最终单报告保留准备、失败、跳过、执行证据；重开准备状态可继续。新回执仅更新准备，用户确认开始后才执行。
- 页面只突出可开始/待刷新目标，其他原因中文统计汇总；完整技术检查留报告。复用已有安装显示名，无法取得时显示 bundle，不额外做私有发现。

## 实现与验证计划

1. 固定 221 源码行为反例：真实过期 eligible 回执不应从可选择列表消失；旧实现必须命中精确断言。
2. `ImageCollection` 同一检查入口产出候选准备状态，新增准备/刷新读取并在实际 start 重验；真实文件覆盖过期、未知、关闭、新进程、保存失败和原配置字节不变。
3. 图片页显式选择与确认，回到前台自动重检；生产 Runtime 前台回执→消费者准备→请求/ACK 回归，以及 UIKit 页面选择/灰按钮→新回执→可确认开始→同报告恢复。
4. 保留全部既有 SDK 限制/清理/关闭恢复及原生/容量/UI；整组本地与独立复核完成后统一提交推送，跟同 SHA 构建、下载验包与离线归档。

不连接手机、SSH 或执行历史被拒私有探针。不把本组修复称作五 APP 私有资源适配完成。

## 同轮后台与续作反馈

用户另反馈切后台后回到缓存管家主页面。源码没有主动 popToRoot/setViewControllers 重置导航；目前不能断定是系统杀进程或某次宿主重建。已证实的两个缺口一并修复：集中容量阶段后台会主动写取消；旧续作清单不识别图片准备/执行所在步骤。

集中容量现只暂停页面计时器，保留同一服务 epoch，前台或页面重建读取原轮结果，不自动重发。普通容量页原有停止语义不变。主页面“继续采集”复用会话选择，恢复到已有图片准备或当前请求；原请求编号与到期时间保持，已失效请求不续租。图片页正常后台不撤销意图；真实返回且前台仍请求恢复。

图片状态保存采用同进程类锁与磁盘期望文档比较，所有写者拒绝旧快照；重发在覆盖全局请求或通知之前核验，防止旧实例撤掉更新的恢复请求。新增真实并发 barrier 验证旧刷新不能覆盖跳过或另选目标。

本地适用验证：8 个 iOS 16.5 arm64 对象编译、42 项相关 Python 回归、17 项原生编排、4 项 Runtime 编排和 42 个 UI 编排场景；对象编译与编排不冒充 Foundation/UIKit 行为，后续仍须同 SHA 云端实际运行。
