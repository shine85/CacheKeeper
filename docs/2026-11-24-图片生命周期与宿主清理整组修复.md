# 图片生命周期与宿主清理整组修复

本组接续已批准的全 APP 资源治理方案。200.1 是已交付的通用缓存阶段成果；本文件记录本轮实现和验收边界，不能据此认定手机主体占用增长已解决。

## 诊断与修复对应

| 诊断发现 | 本组实现 | 验收条件 |
|---|---|---|
| 图片首次后台准备前的旧 eligible=0 拒绝申请时间 | ImageCoordinator 先申请有界后台任务，覆盖异步准备；明确 scheduling completion | 实际 SDK 文件被清理；前台、禁用、过期期间保留文件；旧回调不能结束新任务 |
| 关闭后 Runtime 不重验身份，原调用统计缺失 | schema2 关闭 epoch 明示 notRevalidated，仅记录原调用；schema1 原样保留 | 三版 SDK 实际写入、限制、关闭恢复及 plist/JSON 往返，未知启用身份仍拒绝 |
| 诊断探针与配置通知共用 configure 入口 | 仅有效配置语义变化撤销；重复探针不取消背景清理或重新提交 | 真实 Runtime 同配置进行中／完成后重复调用无新动作，配置或访问变化及时撤销 |
| 抖音私有 Gurd 根由宿主维护白名单与索引 | 只接当前安装版本已核白名单入口，真实 getter 根与系统主容器 FD 身份绑定 | 真实入口准入、同根观察、保护资源可用、重新访问恢复；不以 selector 返回表示完成 |
| 旧 Gurd 回执恢复误用配置 schema／新 producer | 专用有界 no-follow 读器，严格恢复；每操作保留 producer，旧时间不改写 | XML/binary→恢复→Diagnostics/Capabilities/Inventory→JSON；跨版本旧操作不被归为新包 |
| 撤销在最终验证中到达、旧任务重入、后台时间到期 | 最终提交代次边界、独立 token 所有权、旧事件有序历史；过期立即归还自身 token | provider 阻塞时也即时 end；提交前撤销无宿主调用，提交后明确 interrupted；旧 token 不撤新事件 |
| 读取权限失败被压为身份变化 | 保存真实 errno、区分 readError 与身份变化；同范围完整样本才计算差额 | 不可读普通文件保留 EACCES，链接、替换、预算失败阻止完整效果结论 |

## 固定来源及宿主差异

- [SDWebImage 5.21.7 SDImageCache](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDImageCache.m)：实际 owner、串行 IO、删除和写入链；保留 5.21.7、5.15.5、5.10.4 的独立实际 SDK 回归。maxDiskSize=0 表示无大小上限，不能用于禁止写盘。上游版本不能代替百度或 QQ 的实际安装契约。
- [火山 Gecko 2.0.10 固定 podspec](https://github.com/volcengine/volcengine-specs/blob/dad40c3a16e9f8d9d9599eeb95b7f86ba00c391b/mars_gecko_ios/2.0.10/mars_gecko_ios.podspec)：厂商发布包提供接口参考，压缩包 SHA256 `00a48f4247de3c345b31c156163b5a621b2ea987fb8773e022c8273cd83d7a16`。它是接口／二进制参考，未找到本次宿主的完整开源实现，不能称为抖音同版源码。实际准入来自现机 41.2.0/build412021、AwemeCore UUID `cc3b646814e43c7fa8708f1eb5f4adeb` 的类、ABI、IMP 偏移和固定代码窗口双读指纹。
- [Swiftgram MediaBox](https://github.com/Swiftgram/Telegram-iOS/blob/ba54d9823d413f9816e5eee2724da77d5079f4cf/submodules/Postbox/Sources/MediaBox.swift)、[StorageBox](https://github.com/Swiftgram/Telegram-iOS/blob/ba54d9823d413f9816e5eee2724da77d5079f4cf/submodules/Postbox/Sources/StorageBox.swift)、[TimeBasedCleanup](https://github.com/Swiftgram/Telegram-iOS/blob/ba54d9823d413f9816e5eee2724da77d5079f4cf/submodules/Postbox/Sources/TimeBasedCleanup.swift)：保护式删除需要保留引用集合；返回尝试 ID 不等于成功 ID；索引 remove 无完成回调。相同 setMaxStoreTimes 不重复扫描，一次扫描不代表持续限写。

Gurd 仅调用 `clearCacheExceptWhitelist:YES`（`v20@0:8B16`）；保留宿主白名单、小程序／游戏容器、锁定通道，由宿主管理通道队列和索引。任何排除项与实际根重叠时跳过整次宿主调用。报告分开记录 notSubmitted／submitted／enteredUnknown、同根普通文件逻辑量及按 inode 去重的 st_blocks 量，独占物理回收为 notMeasured，限写为 unsupported。当前入口的实际调用线程、真实宿主完成与资源保持仍须真机验证，不把下层有队列推为所有上层入口可任意线程调用。

## QQ／Swiftgram 主体调查结果

只读采集 9 个技术任务全部退出 0，双读及程序身份前后稳定；QQ 三个 owner 的 104 个方法、11 个代码窗口共 5720 字节／遍已核。`deleteQQDisk:` 实际为 8 字节统计 setter；AutoCleanConfig enable/setEnable 仅对象字段，defaultConfig 创建新实例，均不能据此宣称当前宿主策略已生效。ClearCacheEngine 的上传保留、聊天排除、开始／停止入口存在，仍需真实 consumer、保护范围、队列终态和原值恢复合同，未开放自动主体删除。

Swiftgram 13.0/319 已核 11 个程序入口与 17 份固定源文件。保护式指定资源清理仍缺活 MediaBox／StorageBox owner 关系、合法复合 Swift ABI／Signal 回调、草稿／上传／离线／唯一副本保留集及交易完成边界。容量扫描包含原件，不能用 clamp 或 UI 跳转代替安全自动治理。

百度当前 image_filelist 总 3,334,320、deleted=0 是完整只读计数结果；停止空 garbage 路线，不删除有效业务索引来换取 GB 数下降。未来新安装或结构变化由现有统一容器与能力契约增量发现，未知资源明确保留，发现不授予删除权限。

本机 Windows：原生编排 16、图片编排 3、精确失败控制 6、UIKit 编排 42 个用例通过；UI 进程生命周期 24 个用例执行，其中 3 个实际 POSIX 用例明确跳过；清理摘要编排 6 个用例通过。实际 C core、SDK 16.5 ARM64 对象编译分别记录；Foundation／UIKit 无运行环境，实际尝试返回 UNAVAILABLE。这些编排结果不能冒充宿主行为通过。

本轮完整 native 汇总实际为 6 PASS／54 UNAVAILABLE／0 FAIL（整体退出 1），未以不可用代替通过。指定已有 Zig 后，资源分类、图片效果、缩放尺寸、writer C core 四个实际回归均通过。9 份生产源码最终 SDK16.5 ARM64 对象检查通过；Cleaner 保留 7 项原有未使用通知参数警告。首次通用对象检查命令漏加 Vendor 导致 libSandy.h 缺失，按现有 Makefile 的 include 和目标 define 重编通过，没有改动产品来绕过依赖。

统一 native runner 共 60 组，新增 Gurd engine／Runtime、图片 Coordinator／关闭身份／重复探测 5 组；单子命令不超过 60 秒。重复探测的 7 场景覆盖同配置、禁用、访问变化、安装变化、迟通知、合并配置及背景 provider 晚采用策略，并保留精确失败反例。Gurd Runtime 的 13 场景另覆盖真实安装服务阻塞时主线程即时撤销，以及通知早于 provider 时单次事件／令牌。实际 Runtime 测试运行生产 provider、Source 方法、目录采样和原子保存，只替换 UIKit／安装服务／加载宿主 ABI 边界，不能代替本机抖音接口认证。iOS 对象检查中完整 UIKit 头对应的最小 UIApplication 测试替身产生未实现其他方法的警告，日志保留；生产对象检查与测试行为分开报告。

整组独立复核后统一普通提交／推送，再跟进同一提交所有原生、UIKit、容量、原生 RootHide SDK16.5 arm64/arm64e 编译和真实 deb 检查。云端失败先集中修复再复验，完整成功、附件 hash／标签 SHA／身份／新类核验前不交付用户测试包。手机未安装本组新包、未执行清理、未修改策略或权限；成功包和最终验证结果另行记录。

## 成功新包后的集中真机步骤

1. 开发侧确认 Release／deb 版本与 hash 后，取得本组安装与指定清理范围授权再安装；保持手机 SSH 窗口，用开发侧采集当前宿主版本／运行回执，用户无需手查目录或提供安装包。
2. 先导出 A 报告：新包版本、目标 APP 开关／模式、当前目录和宿主回执。启动抖音、QQ、Swiftgram／百度按原使用顺序浏览后回到桌面，等待后台操作，再导出 B。Gurd 看各 event 的 submission、phase、before/after、errno，不以容量置零或开关开启判有效。
3. 同一配置重复请求诊断，确认没有新提交或取消合法背景工作。随后关闭目标 APP 总开关，浏览相同内容再后台，导出 C：图片原调用恢复、未新增限制；Gurd 不提交。再开启并重新前后台，导出 D，确认新事件及旧回调不误撤销。
4. 开发侧核对 A–D 的时间、producer／event 与当前安装关系。集中检查账号、草稿／待上传、离线下载、保留通道／小程序可用和重新浏览恢复；如发生失败提供同轮崩溃日志和操作顺序。Gurd 任意排除重叠须明确 skipped，不能测完后才补造保留规则。
5. iOS16 现机结果仅说明这台设备；iOS17、卸载恢复、私有主体限写与独占物理收益另须实际验收。QQ／Swiftgram 尚缺完整安全合同，不把本轮源码或测试通过当主体治理完成。

既定方案剩余条件：本组云端真实回归／编译／验包、实际宿主准入与保持／恢复；QQ／Swiftgram 安全可执行合同。最终产品仍缺所有主体增长的安全自动治理、必要数据全链保持和跨版本／iOS17 证据，不能用主观百分比替代这些条件。
