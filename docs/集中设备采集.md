# 集中设备采集

后续统一使用“电脑准备通用工具包 → 手机保存一次 → 现有 SSH 连接中批量采集 → 一个目录回收报告”。工具包不是插件 deb；保存后无需用户解压、签名、安装或手工查每个 APP 的目录。

在仓库根目录执行当前已实现的静态批次：

```powershell
python -X utf8 scripts/collect_device.py
```

入口自动读取已认证 SSH 会话，不需要填写会话 ID、账号或密码。连接尚未建立时，先运行项目现有 `连接手机SSH.bat`。结果写入 `packages/采集报告/批次采集/<runID>/collection.json`；失败也保留本批回执，不覆盖旧报告。

静态采集器、严格解析器和脚本模板现随仓库保存在 `scripts/device_collection_sources/`，有固定来源 SHA，不再依赖旧 `tmp/` 文件。已在不含历史目录的干净副本运行完整 CLI → Bash → SDK 对象回执测试。2026-11-26 首次真机批次枚举 309 项、取得 284 项主身份；连接中断后按原身份补完 205 个明确未尝试项，最终共 283 份 SDK 回执。合并结果为 277 项声明范围完整、6 项部分完成、25 项缺主身份、1 项结果未知，全部回执长度与 SHA 离线核验通过。详见 [当日批采记录](2026-11-26-全APP批采进度与边界.md)；这仍不能证明全机私有缓存能力已适配。

SSH 传输继续使用已认证的本地适配器。当前工作区自动使用 `scripts/persistent_device_ssh.py`；新 checkout 可显式复用已有目录中的适配器：

```powershell
python -X utf8 scripts/collect_device.py --transport-adapter <已有工程>/scripts/persistent_device_ssh.py
```

该适配器及其 `device_ssh_protocol.py`、`device_ssh_memory.py`、认证状态保持在已有位置，入口按适配器自身的 `BASE` 校验同一会话。缺少适配器或有效会话会明确退出；脚本不建立连接，也不把密码、密钥或认证状态复制进工具包。采集源码可复用与手机运行已验证是两项独立结论。

当前静态范围是本次系统登记的全部 APP：版本、build、主程序 UUID 和精确 Mach-O load commands。逐 APP 隔离失败，区分已采、失败、已提交但结果未知、未尝试；批末复查登记成员变化。报告不包含容器路径、原始主头或应用数据。主程序 UUID 相同不自动复用旧 SDK/ABI，嵌入镜像、资源 schema 和容器关系还需各自核对。

SDK 阶段已接入现有静态采集器：每个 APP 在当前版本与主 UUID 匹配后检查19个固定SDK候选，只读取声明的未加密技术段，每次原始数据最多2MiB、输出最多4MiB、单APP最多120秒。范围超限、加密、身份变化和截断保留为partial或拒绝；不会把“未发现候选”当成不存在任何其他SDK。原始技术片段按SHA保存，主报告只保存本地引用。

现有 runtime 适配按技术证据产生集中前台待办；静态入口不启动 APP、不 attach、不删除缓存。运行时服务及 attach 另按集中窗口明确授权，不能把某一 APP 的准备完成当成所有 APP 私有资源已适配。用户要求晚上不连手机：晚间只做本地开发与验证，真机批次等白天明确可连接后执行。

控制器等待预算默认为 1800 秒；当前 SSH owner 仅有单任务相对期限，排队任务可能晚开始，因此不宣称设备绝对总截止已生效。一次批次完成也不等于清理、空间效果、必要数据保持或恢复能力已验收。

## 中断后仅补元数据缺项

先确认原批次已终态和当前连接已认证，再执行：

```powershell
python -X utf8 scripts/collect_device.py --resume "packages/采集报告/批次采集/<原runID>/collection.json"
```

入口只选原报告中有主身份且明确未尝试的 SDK 项，不重新枚举或重扫全部 APP。原文件保持不变，新报告放在同级 `resume-<父报告SHA256>/collection.json`；同一父报告重复执行会拒绝。后续再次中断时，从新的终态子报告续采。缺主身份、失败、部分回执和结果未知的项不会被自动重试。

每个待采项仍由现有 SDK 采集器复查当前登记、版本、build、主 UUID 及采集中身份稳定性，只使用原固定 SDK 白名单。身份变化保留缺口；不会扩大到代码窗口、运行时附加或应用数据读取。`sdkSummary` 独立于主身份统计，续采另按 `historical/fresh` 区分来源，`primaryIdentitySource=parentReport` 明示主身份来自父报告，不能将历史成功当作本轮重新验证。

## 五 APP 集中准备

已同意的目标流程是工具一次部署到手机、五个 APP 集中操作、统一回收一个报告包。完整手机执行器尚不可用：此前运行时取证被自动安全审核以 `Potentially unintended activity` 拦截；不能通过更换为手机本地工具重试该操作。

当前可在开发电脑离线整理已保存的终态报告：

```powershell
python -X utf8 scripts/collect_device.py --prepare-session "packages/采集报告/批次采集/<终态runID>/collection.json" --output "packages/采集报告/集中准备/五APP离线证据.zip"
```

可把同一轮的已保存阶段报告直接并入该 ZIP，使用 `--phase-report STAGE=JSON[=SHA256]` 重复传入，例如 `prevent=限制并清理217.1.json=<SHA256>`、`clean=只清理217.1.json=<SHA256>`、`disabled=关闭217.1.json=<SHA256>`。阶段归一化结果写入 `session.json` 的 `phaseReports`；`capabilityGate` 按 APP 输出 `ready` 或 `blockedByCapability`。现阶段私有资源操作模块未实现，五项均会阻断执行就绪。此改动方便一次整理多阶段证据，不代表已有手机执行器。

输出父目录须已存在，ZIP 必须是新文件；同名文件不会覆盖。`--prepare-session` 与 `--resume`、`--transport-adapter` 不可混用，离线入口不加载传输适配器，不产生手机任务。

ZIP 固定包含 `session.json`、`README.md` 和 `manifest.json`。五 APP 为抖音 Gurd、QQ、百度网盘、京东、Swiftgram；仅输出保存身份、静态回执摘要、来源 SHA 与待补证据。原报告链、回执和技术片段只作本地读取/哈希核验，不复制完整登记表、会话、容器路径或二进制。

生成成功只表示离线准备完成。包内明确 `executionAvailable=false`、`effectVerification=notPerformed`；缺身份、部分采集与未知状态保持原义，静态完成不会升级为私有缓存适配成功。此包不需要放到手机上，也不要求用户现在按 APP 做操作。待完整执行器通过验证且相应取证操作可执行后，再提供一次集中的手机步骤。

为定位实际大占用和无效重复采集，可加 `--diagnostics "packages/采集报告/综合.json" --baseline-diagnostics "packages/采集报告/关闭.json"`。比较报告由开发侧选定，baseline 可省略；不能用其他版本的保存记录声称同一安装的新行为。输出保留主/共享/扩展根以及标准目录分类、partial、producer 版本、组件是否与前次相同；不导出私人路径。相同组件标 `unchanged`，新导出时间不会自动变成“已重新采集”。分析器只验证所用字段，不能替代生产 Objective-C 的完整 schema 校验或真机验收。

WQManager 固定源码对照及本机实际占用见 [复核与方案修正](2026-11-26-WQManager复核与集中采集修正.md)。该项目的标准缓存清理不能覆盖本机 QQ/百度/京东的大部分 Documents，或 Swiftgram 共享媒体；不得将其测试夹具路径作为可删白名单。
