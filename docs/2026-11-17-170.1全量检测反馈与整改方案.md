## 扫描慢的已确认机制与证据边界

1. `AxsCacheKeeperScanService` 每次发布都会读取、解析、递归校验整份 `snapshots.plist`，随后重写全部 APP 历史；创建任务、退役任务也重新读取它。当前只有扫描服务写入此文件。
2. 通过已校验主机密钥的 VPN SSH 完成只读检查，手机安装版本为 170.1。实际历史文件 **11,216,659 字节，XML 格式**。读取一个已知布尔字段三次的整命令耗时为 0.18、0.20、0.20 秒，文件前后属性一致。此测量包含工具启动与解析，不是生产调用链性能剖析，不能据此精确拆分 37 分钟。
3. 当前扫描每次只推进一个目录的一个分片，然后固定等待 100 毫秒。2,185 个分片仅计划等待就约 218.5 秒；空目录和小目录也支付相同间隔。该数是代码调度成本估算，不是设备实际等待时长测量。
4. 进度按每任务每秒发布，而 4 个活动批任务共享串行队列；大文件保存本身变慢时，下一次任务回合常已满足发布间隔，产生持续的全量读写开销。当前回执没有阶段耗时，尚不能判定 LS 元数据解析、文件枚举和写入各占多少。
5. 手机 `plutil` 不是 macOS 同名工具：第一次 `-lint` 返回未知 keypath，**没有完成校验**；后续按实际 `-help` 使用只读 `-key` 成功读取。不执行手机文件格式转换，不改设置、权限或缓存。

## 本轮实现范围与不变量

沿用既有工程、SDK 16.5、RootHide、双架构和包身份。用户已要求出方案后实现、整组验证后统一交付，无须重复征询同一执行许可。

### A. 扫描吞吐与持久化

- 在扫描服务串行队列内复用已校验的历史快照，每次仍读取实际文件字节，仅在与已校验字节完全一致时复用解析结果；不依赖可能保持不变的 inode、长度或 mtime。外部替换、损坏、权限错误必须重新读取或明确失败，不能用旧缓存掩盖损坏，不能覆盖未纳入的新记录。
- 保存历史使用原子二进制 plist，保持同一路径、字段、日期类型及全部读者兼容；只在成功保存后更新内存视图和批次完成数。旧 XML 自动可读，不清除既有历史。
- 保留原有每任务首条、每秒与终态发布节奏，暂不增加全服务发布合并；先减少每次发布的解析与 XML 展开成本。单项与批次维持公平轮转。
- 调度继续保持分片和轮转，缩短小目录之间的固定空等，保留有界工作和取消检查。不能直接取消上限或把不完整改成完整。
- 新增 `scanPerformance.plist`，按扫描服务的一个连续活动周期记录总经过时间、同步工作、容器解析、发现、枚举、历史读写耗时与次数、读取字节量。周期可包含并行单项与批任务，不能当作单个 APP 或专属批次耗时；不含计时文件自身写入成本。首条、每秒和停止后保存小型样本，最终样本包含终态历史写入。导出字段严格白名单，旧记录显示缺失，不输出路径、用户内容或资源名字。批次增加 `started/updated/finished`：`started` 为首次 running 回执的保存时间（在首组发现之后），并非点击时刻；`finished` 是终态回执保存时间，不能用其差值替代服务活动总经过时间。

### B. 宿主与资源准入证据

- 继续只读核对百度安装镜像与实际运行镜像的关系、路径视图与 FD 属性差异；磁盘原始可执行文件头已与旧契约一致，运行时来源尚需核实。
- 核对 Swiftgram 注入条件与宿主观察缺口，分清未运行、没有发起观察和有明确错误；不凭空扩大注入范围。
- 百度两个拒绝点在取得根因证据前保留安全边界，不删时间戳校验，不把 SDK 方法存在等同于可操作。
- 微信、风起云涌不做专项适配；统一扫描仍按用户实际的全量列表工作。

## 开发侧验收

1. 真实临时目录与旧 XML 历史上重现：多 APP 分片过程中重复读取/写入不得随每个任务回合线性放大全量解析。验证二进制持久化可被当前读者消费、记录不丢、历史次数不虚增。
2. 覆盖外部替换/损坏、保存失败、取消、批次替换、服务重启、单项与批任务重叠；批完成必须有同 token 的持久终态。检查容器/目录变化与符号链接拒绝继续有效。
3. 以 134 个 APP、每个 24 根与四次历史构造超过 8 MB 的旧 XML 元数据，做真实原生行为回归和阶段耗时记录，不能用 Python 模拟替代 Objective-C 实跑。Windows 无 Foundation/UIKit 时明确 UNAVAILABLE，完整云端验证后才能交付。
4. 整组源码和测试复核后统一提交推送，跟进同提交全部原生、UIKit、RootHide Theos 编译、deb 内容与 Release 核验；不为单个失败基线反复发包。
5. 最后只安排一次集中手机验收：全量检测时间与完整性、停止/重试、四个目标 App 的宿主与 SDK 结果、关闭限制后的恢复。私有资源安全契约、物理释放归因、必要数据保持及 iOS 17 真机证据仍是最终产品缺口。
