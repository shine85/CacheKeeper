## 本次确定缺陷与本地修正

301 个库存条目中，163 个未进入 APP 回执读取集合的登记项，被 Gurd 库存摘要误标为 `invalid`；同项 image/webKit 为 `notObserved`。211.1 报告已存在这一问题，不是 214.1 新增回归。

根因是 `AxsCacheKeeperStorageInventory.m` 的 Gurd 摘要入口把不存在的 wrapper 交给共享坏输入判定。现只对 `nil` 返回 `notObserved`：真正读取后文件不存在仍为 `missing`，`NSNull`、字符串、坏字典和坏回执仍为 `invalid`，不改变共享 source 判定或 Gurd 清理范围条件。

`tests/storage_inventory_tests.m` 已增加真实 `登记 → Diagnostics → 库存 → JSON` 链上的未读取/已读取缺文件断言，以及公开库存聚合入口的损坏 wrapper、原失败状态和合法 schema 2 回执回归。该修改不解锁 Gurd、不改变清理或写入限制策略。

验证情况：报告断言实际执行退出 0；两名只读代理分别核对容量、Gurd 与修复边界；源码及测试 diff 检查通过。Foundation RED/GREEN runner 已实际调用，返回 **UNAVAILABLE / 2**，当前 Windows 缺 macOS/xcrun，未运行产品行为测试。该本地修正尚未编译成新包、未发布、未在手机安装；应并入下一组功能修复的 macOS 原生验证后统一交付。

## 既定方案剩余项与下一组工作

1. **Gurd 实际能力：**仍缺宿主真实清理候选快照、初始化终态及 writer 共同保护范围的证据。继续按已批准的真实清理范围方案完善契约；范围未证前不提交。验收仍为连续两次 submitted，before/after 均 complete，并确认保留项完整。
2. **非空限写与恢复：**先在已确认 SDWebImage 的米家做同版本、同配置轮次的阳性对照：限制模式 attempts>0 且 blocked>0，只清理/关闭后新写入恢复 allowed。其他 APP 的真实写入路径由开发侧统一采证，缺 SDK 回执不能让用户靠反复浏览补足。
3. **QQ、百度网盘、京东及其他 APP：**复用已准备的全 APP 静态批次，集中核实当前镜像身份、接口与适配拒绝原因，再针对有证据的资源契约统一实施。方法存在、容量置零、报告状态正常均不等于可安全清理。
4. **扫描与容量：**本次容量重测步骤已完成；Swiftgram 旧失败缺结构化原因不能补造。后续新扫描若失败，必须验证轮次包含阶段/errorCode；Music 的权限缺口保持可见，不扩大权限掩盖它。

距离最终目标还差：各 APP 私有缓存的用途、可重取与必要数据保留契约；真实清理、非空限写和关闭恢复；可归因物理效果；新增/升级 APP 自动增量核验；iOS 17 与卸载恢复的实机验证。这些不能用本轮报告修复替代，也不用主观百分比表示完成度。
