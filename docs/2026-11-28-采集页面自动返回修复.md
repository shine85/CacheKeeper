# 采集页面自动返回修复

新增文件，无旧版本可备份。用户再次明确：切出打开 APP 后回来停在缓存管家主页面，手动“继续采集”不满足目标。

## 证据与边界

224.1 的 CKSettings 前台回调只刷新列表，自动恢复入口缺失。图片页将不在导航栈视为离开，诊断页和宿主页也在移除时中断；这些条件不能证明用户主动返回。手机上导航为何被卸载仍无运行证据，不把系统终止或 PreferenceLoader 重建当作已证实原因。

本轮复用 SDK 16.5 UIKit 公共 UINavigationItem.backAction（iOS16起）识别返回按钮，交互返回只在真实 transition 未取消后处理；不用全局 hook 或替换宿主导航代理。系统状态恢复需要宿主应用配合，插件不能控制 Settings app/scene delegate，因此使用采集专属返回位置。

## 实现方案与不变量

- 单一固定返回记录只保存会话 basename、sessionID、page 枚举与 token；原会话文件仍是阶段和请求唯一事实源。写入前检查原会话，更新/清除按 token 比较，旧页面不能清除新会话。
- 用户进入采集流程时登记；后台、普通卸栈与 dealloc 只停止 UI，不把它们当取消。显式返回、取消、跳过、报告完成清除对应意图。真实交互返回取消时保留。
- CKSettings 前台/出现合并调度，仅完整可见导航分支、无遮挡/过渡且仍是原 root 时重建原会话页面链；已有页面时不重复推入。不选择“最近会话”，不新建、不重发、不续租。
- 自动恢复只读已有状态；图片原租约过期照常显示，恢复未确认不冒成功。已封存报告不自动跳回采集，坏记录只报告一次不循环推页。宿主预检内存请求若已丢失显示中断，须明确重试，不自动重发五 APP 请求。

## 计划与验证

1. 固定224 root源码的真实UI RED：已有有效意图、宿主卸栈/新root出现后应自动到图片页，旧实现精确停在root。
2. Foundation 文件覆盖返回记录合法性、相对文件与session绑定、旧token清除、新会话替换、坏记录、封存会话。
3. UIKit 覆盖准备/执行/过期、容量同epoch、宿主中断、重复通知、旧栈仍在、真实返回/取消、交互取消、导航分支不匹配与重建重复恢复。
4. XCUITest 实际 Home→系统另一APP→返回Harness；测试宿主可销毁重建root，必须无手动继续按钮回到原session。它证明生产恢复逻辑在模拟器宿主执行，不冒充真Preferences进程行为。
5. 本地对象编译、宏前置、相关回归、独立复核后统一提交；同SHA完整原生/UI/SDK/容量/Theos/deb与离线证据闭环后再交付。
