# CacheKeeper 0.7.2-188.1 集中真机验收

适用版本：0.7.2-188.1。源码 777afd213d3a186439e9cc4be8df0ac434f4b78d；Actions 44895270245 的原生、UIKit、容量页面、Theos 和发布五作业全部成功，本地下载验包通过。

开发侧已完成原生51/51、容量页面25/25、全部UIKit套件、Theos编译和实际deb检查；现在可安装后执行以下手机步骤。当前手机不连接 SSH；开发侧补采待连接条件恢复后进行。未知私有文稿、数据库、原件和媒体仍保留。

## 1. 安装并确认版本

下载本轮交付的 `.deb`，用现有包管理器安装，按提示重新加载桌面。完全退出设置后重新打开「设置 → 缓存管家」，确认显示的完整插件版本与交付一致。保留已有开关、目录排除和模式，不重置配置。

## 2. 全机只读测量与停止恢复

1. 关闭被测 APP，打开缓存管家诊断页。
2. 点击「重新测量全容器占用 · 只读」，等页面出现本轮终态；记录是否完成、失败或不完整。
3. 点击「汇总已保存诊断」再「导出报告」，保存为「新版-全容器完成.json」。汇总和导出不会再次测量磁盘。
4. 再启动一次测量，在进度变化时点击「停止全容器测量」，等待停止确认，再汇总并导出「新版-停止.json」。若页面显示停止尚未确认，保留实际文字与等待时间，不自行判定停止成功。
5. 重新开启新一轮，完成后导出「新版-重测.json」。这三份用于核对旧轮停止、新轮独立、晚到回执及容量失败原因。

测量只读，逻辑大小、已分配字节、父子目录容量和卷空间变化不能当作安全可清理量或独占物理释放。

## 3. 已适配图片与目录的三种状态

逐个 APP 集中执行；选可以重新获取的测试内容，并核对已有草稿、离线原件、消息、登录状态和用户排除目录。不要人为修改真实业务目录。

1. **只清理**：正常浏览可重新获取的图片约 1–2 分钟，切后台但先保留进程。查看图片实例、来源、动作状态和更新时间。SDK 清理需要存活宿主，不先划掉 APP。应恢复原始写盘，清理是否生效看同次动作前后证据及重新读取。
2. **限制缓存并清理 / 自动**：使用新的可重新获取内容，再切后台。核对真实受控实例、限制写盘计数、同次清理结果和必要数据保持；开关开启、容量置零、API 完成均不能单独证明生效。
3. **关闭 APP 总开关**：重新打开 APP 并使用新的测试内容，确认恢复原写盘和正常读取，不再新增插件动作。记录关闭前后更新时间。
4. 每种状态结束后，在诊断页「汇总已保存诊断 → 导出报告」，按「APP名-只清理 / 限制并清理 / 关闭恢复.json」保存。

标准 Caches/tmp 的退出清理可另按既有步骤：正常使用 → 检测目录 → 退出 APP → 等合格缓存成熟和清理终态 → 检测目录 → 重开验证。检测目录本身不触发立即删除。保持独立网络选项原设置；模式切换不应擅自改网络开关。

百度、QQ、抖音和 Swiftgram 的未验证私有目录继续保护。本次新增结构识别不是这些目录已经允许清理，也不是安装版本契约已经全部通过。

## 4. 页面和旧功能回归

测量或检测进度变化期间，集中检查搜索输入、清除、取消、滚动、APP 详情返回、诊断返回；检查列表更新时间、失败详情和原有排除。若出现安全模式、崩溃或必要数据异常，保存发生时刻、APP 和操作顺序，以及同时间的脱敏崩溃报告。

## 5. 反馈文件

- 三份扫描报告：「全容器完成」「停止」「重测」。
- 每个被测 APP 的「只清理」「限制并清理」「关闭恢复」报告。
- 一段操作顺序：插件完整版本、APP 版本、各阶段模式、停留时间、资源能否重新读取，以及登录/草稿/离线原件是否保持。
- 只在有异常时附脱敏截图或同时间崩溃报告。

无需手工找目录、导出数据库、上传文件内容或准备同版本安装包。开发侧从报告和已有技术档案核对 owner、写入/删除/恢复证据，仍缺的安装版本契约由开发侧补采。
