# 通用安装与缓存续修

## 本轮状态

基线为 `897259fcd3e846662379fbce97896ed8abfd76ff` / 0.7.2-109.1。本轮实现已落盘，原生红绿、UIKit、RootHide 与 deb 验证待 CI；没有新包成功结论。设备仍安装 105.1，未部署或执行资源清理。

## 已实现的行为

- 诊断按每轮当前安装列表与配置的并集汇总已有记录，新装未配置 APP 也出现并保持禁用。列表来源缺失、未在快照中出现、安装文件无法核验分别标注。每轮进度固定；汇总不扫描容器内容，不改配置，手动导出才生成文件。
- Settings 和诊断共用后台安装提供器；每个调用方持有独立内存缓存，未变包只核验元数据并复用快照，新增或变化项才重新读取有界 Info.plist。系统仍枚举的已确认巨魔 APP 暂缺安装 URL 时保留显示分类，同时撤销旧身份。
- Scanner 将安装包身份加入作业条件。同版本构建替换、Info 或主程序变化、安装位置改变、安装信息不可用，都会停止旧作业并撤销发现/完成/待识别缓存；新作业重新核验。身份只在内存，不是代码签名验证；每根/批次采样仍有检查至删除之间的窗口。
- NSURLCache 的两种创建入口在限制已启用时把磁盘容量压为零，保留内存及其他参数；关闭后恢复 APP 请求，后续明确设置（包括零）优先。真实初始化器在锁外调用，初始化期间的策略变化与替换返回对象均有回归。此接口不覆盖 WebKit 或任意 SDK 自建存储。

这些通用行为不依赖每个新 APP 的版本名单，也不替用户启用未配置 APP。标准缓存仍使用既有 iOS 用途约定、排除和必要保留规则。私有媒体与下载资源仍须具备资源所有者、真实调用上下文和可恢复集合。

## 验证方法

`run_diagnostics_red.py` 和 `run_network_initialization_red.py` 从固定基线取旧生产代码，搭配新回归，只有分别触发安装漏项/初始化非零磁盘容量的行为失败才算红灯；编译失败不能替代。

完整原生回归包含真实 bundle 文件替换与 CleanupJob/Sweep 删除对照、未变安装对象复用、诊断集合与零写入、Foundation 初始化参数及容量恢复。UIKit 使用实际 Settings 源码和模拟 Preferences 宿主，不能替代系统设置真机验收。Theos 与 deb 分别核验 SDK 16.5、RootHide、arm64/arm64e、作者和完整版本。
