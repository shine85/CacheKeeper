# 五 APP 宿主集中预检

## 问题与本次修改

214.1 保存报告中，QQ、京东、Swiftgram 的宿主 producer 仍为211.1，百度为202.1。仅导出新报告不能证明目标APP加载了新插件；原因可能在加载、配置读取或保存链路，现有记录尚不能区分。

诊断页新增“五 APP 宿主集中预检 · 只读”，一次发起抖音、QQ、百度网盘、京东、Swiftgram 的既有 HostEvidence 请求。逐项显示本轮响应、插件版本、已有访问结果、APP开关配置可读性和诊断发布状态；超时/取消/通信失败分别保存。只使用原协议，未新增服务端、授权请求、进程附加或私有资源读取。

页面后台暂停UI轮询并保留请求，回前台继续读取；实际返回/关闭页面取消未完成项并释放令牌。终态写入原 `Status/<bundle>.hostObserved.plist`，由原总报告汇总。写入失败保留本轮结果，单独“重试保存失败项”不重新请求APP。原appEnabled配置与资源不修改。

这些信号仍未经身份认证；预检响应不证明清理、限写或私有资源契约。网络probe会重新配置策略，本功能没有调用它。此前被安全系统终止的私有取证任务也没有通过本入口重试。

## 成功构建后的集中手机步骤

当前文档描述待完成构建的步骤；只有交付消息提供成功包后执行。

1. 正常安装交付的新包并按包管理器提示完成必要重启用户空间。进入设置→缓存管家→诊断→“五 APP 宿主集中预检 · 只读”。
2. 点击“开始新一轮五项预检”，在5分钟内依次打开抖音、QQ、百度网盘、京东、Swiftgram，再回预检页。无需SSH，不清理数据，不要求反复浏览制造计数。
3. 查看五项终态。版本不同、配置不可读、保存失败或超时均保留事实；先由开发侧定位这些结果，不当场重复整轮。若仅页面保存失败，点“重试保存失败项”即可，无需重开APP。
4. 返回诊断页，点“汇总已保存诊断”→“导出报告”，保存一个JSON到 `packages/采集报告/宿主集中预检/`。若某APP未安装或未打开，报告可超时，不把它当未注入。

此步骤只验收集中宿主预检，不要求同时进行容量全盘测量。已有214容量基线继续复用，是否需要下一次同范围测量由本轮证据决定。
