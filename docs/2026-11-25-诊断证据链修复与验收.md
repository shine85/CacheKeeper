# 诊断证据链整组修复与验收

本轮按 2026-11-24 已批准的设计继续修复。提交 `631ca43` 的原生 60 组、容量页面 32 项和三个精准反例已通过；UIKit 九组中八组通过，三版 SDWebImage 实际阻写与关闭恢复均通过。搜索页导航断言失败后，测试仍继续误按按钮，并在 900 秒超时后留下未闭合结果包；该提交没有生成新 deb。提交 `e0a1186` 正在验证对应测试修正。

后续复核发现 Gurd 虽保留同一 cursor 分片，但仍有每轮 4 秒总 deadline；到期后关闭 cursor，下一 operation 重新开始。因此此前“已分片”不代表“已修复 4 秒采样超时”。当前补充候选已移除这层固定总 deadline，以真实后台任务到期、回前台、配置或身份变化终止；条目、深度和数值上限继续保留，范围未证明时仍不采样、不调用宿主。新增真实文件回归在每片后将测试时钟推进 5 秒，检查连续两轮同 cursor 的 before/after 完整；另在已有非零采样进度后触发后台到期，检查 partial 下界、零新增提交和句柄释放。固定 `e0a1186` 旧采样器须精确失败于旧 4 秒上限。该补充实现与真实行为回归须随最终提交重新验证。

## 诊断发现与修复对应

| 诊断发现 | 本轮实现及边界 | 开发侧验收 |
| --- | --- | --- |
| Gurd 全根采样超时，清理候选集不明 | 同一进程、同一 cursor 跨队列分片累加，移除独立 4 秒总截止，按真实生命周期终止；partial 仅为下界。实际候选谓词尚未证明，生产继续记录 scopeUnproven，不调用宿主清理 | 原生文件系统回归覆盖 cursor 复用、跨旧 4 秒预算、计数不重复、非零 partial 关闭句柄、生命周期撤销；旧 4 秒采样器与旧符号链接实现分别运行精准反例，不以新版本替身代替 |
| 把清理 API 或累计 blocked 误当本轮限写效果 | canonical 导出移除跨生命周期 writesBlocked，保留严格 writer epoch；缺观测或零 attempts 保持 unknown。界面分别说明 NSURLCache 独立选项和 SDWebImage 模式限制 | JSON 回归区分 absent、零 attempts 和真实 blocked；三版真实 SDK 验证 prevent 阻写、关闭后恢复落盘 |
| Swiftgram 历史缺失败阶段与错误码 | 最近轮次携带限长诊断；旧记录 unknown；计数饱和时记录截断和测量不完整，保留 omitted 数量 | 原生历史/导出断言检查错误阶段、域、码、计数、截断与脱敏；终态等待不假设固定 tick 数，遵循最近四条历史上限 |
| 容量导出可引用旧轮次或非法绑定 | 只接受明确字段集合；epoch、终态、结束时间及汇总时间一致才可导出；重测使旧汇总失效 | 精准反例恢复旧字段数量校验并命中 unknown binding fields；正常投影、逐字段缺失和新旧 epoch UIKit 用例 |

容量旧 CI 日志中的大量 FAIL 来自预期的变异反例。已核实的正常版本失败是未知绑定字段被接受；不据此修改取消请求与 epoch 状态机。诊断旧版本反例另补真实 Installation.m 链接依赖。

## 当前验证边界

- Windows 可执行 Python 编排、契约检查；仓库现有 Zig 可编译执行写入计数 C 核心。
- Foundation、UIKit、实际 SDWebImage SDK、Theos 与 deb 需由本轮同一提交的 GitHub Actions 验证。旧 SHA 的成功或失败不能替代当前修改结果。
- 六份既有报告的 collection.mode 为 savedRecords、rescanned=false，不能当作本轮新扫描或新的 writer 操作。面板版本与宿主回执版本独立，不据文件名推导已安装版本。
- 2026-11-25 已复用用户恢复的 SSH 连接完成只读核验：现装 Aweme 仍为 41.2.0/build 412021，五段固定代码窗口匹配。已补采候选元数据来源、保留分支与队列调用证据；完整谓词及动态快照一致性仍未证明。本轮没有触发手机宿主清理。

## 新包通过构建和验包后的集中真机步骤

1. 安装最终交付的完整版本号对应 deb。重新打开设置面板及待测 APP，确认面板和宿主回执均来自该版本；旧宿主回执不能替代新操作。
2. 以已确认接入 SDWebImage 的 APP 做阳性对照。先在只清理模式打开此前未浏览的图片，再切后台，记录新 epoch 是否 attempts>0、allowed>0；随后切限制模式，再打开另一批未浏览图片，确认 attempts>0、blocked>0。最后关闭限制，再打开新的图片，确认 allowed>0 并能正常读取。若 attempts=0 或未记录，结论为未触发，不能写为限制有效。米家只作为历史候选，旧 API completed 不证明当前 writer 已触发。
3. 对 Swiftgram 发起一次普通扫描。若失败，最近轮次和导出应保留阶段、错误域/码、计数与截断；没有失败时保留真实成功，不制造错误。
4. 执行“重新测量全容器占用”，等待终态。随后重新汇总，再导出；重测中或重测后未重新汇总时应禁止导出旧报告。局部权限失败应原样呈现，不补零、不伪装 complete。
5. 报告统一放到 `packages/采集报告`，文件名带新包完整版本和阶段（只清理、限制、关闭恢复）；附实际操作顺序及观察到的异常。开发侧逐项核对 epoch/版本/attempts，不要求用户手工寻找私有接口。

## 剩余项与最终目标

- Gurd 仍需固定宿主实际清理候选谓词及所有排除条件的证据；证明后才可验收连续两个 operation submitted 且 before/after complete。测试 fixture 的成功不得解锁生产。
- 本轮其余三项在 CI、验包通过后仍需新版本设备集中验收，不能用既有历史报告替代。
- 本轮不扩大到抖音 ALog、其余 12 个无回执 APP、D 后数据完好性。最终全 APP 主体占用治理、私有资源安全清理、真实空间效果及 iOS 17 验收仍有缺口，诊断修复不代表这些能力已经完成。
