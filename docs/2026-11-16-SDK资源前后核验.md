# SDK 资源前后核验

本程序用于开发侧核对已证明归属的 SDK 缓存目录。它不发现目录、不调用缓存 API、不安装或修改手机文件、不读取文件内容。完整实施与真机验收仍受 [154.1 续修计划](superpowers/plans/2026-11-16-154-feedback-and-product-completion.md) 约束。

## 先决证据

开发侧先从同一宿主的真实缓存 owner 确定当前目录，并关联具体版本、进程实例和操作。仅凭目录名称、SDK 类存在或 SSH 目录可读不能证明归属。缺少这条关系时继续保留资源，不扩大扫描。

`scripts/owner_snapshot.py` 的 capture 子命令读取开发侧私有授权清单。清单包含 schemaVersion=1、root、rootDevice、rootInode、comparisonKey、ownerEvidence 和 authorized=true；其中 comparisonKey 是每轮本地随机 32 字节的十六进制关联密钥，ownerEvidence 是已审核归属证据的 SHA256。密钥仅用于名字去标识，不是认证凭据。不得提交清单或在聊天中发送路径、密钥。授权布尔值也不能替代用户实际授权或宿主证据。

普通应用沙盒 root 必须来自真实 owner/API。越狱工具自身路径使用项目当前 Roothide API 解析，不能把越狱根前缀套到应用目录。程序从 `/` 开始持有目录 FD，逐组件 NOFOLLOW 打开，只接收完全定位且无符号链接的输入。任何别名必须由已证明的来源事先解析并重新核对，程序拒绝猜测或自动改用其他根。

## 开发侧执行

在具有 POSIX descriptor API 的已批准执行环境运行：

```sh
python3 scripts/owner_snapshot.py capture /local/private/authorization.json
python3 scripts/owner_snapshot.py compare /local/private/before.json /local/private/after.json
```

输出由调用方保存到本地 `tmp/`。程序只向 stdout 输出脱敏结果；错误只含固定类别与 errno，不含原始 OSError 路径。采集不提供远程连接或自动安装功能。Windows 可执行比较器测试，实际 FD 采集必须在 POSIX 环境验证；当前手机是否有可用 Python 运行时尚未确认，不能宣称已在手机运行。若设备环境不足，先准备等价原生工具或已验证的只读执行通道，取得具体部署授权后才执行，不能让用户手工寻找缓存目录。

每次采集限制为 15 秒、100000 个目录项、64 级深度。错误、身份变化、跨设备目录或超预算都拒绝该次结果。原始名称只在进程内参与 FD 定位，报告用每轮私有 HMAC 关联。普通文件仅 stat，不 open/read；符号链接与特殊文件只计数，不跟随。硬链接按同次 dev/inode 去重，根、目录和条目均在读取后核对完整元数据。

这仍是持续时间内的有界观察，不是原子文件系统快照。已访问文件随后发生的并发写入可能无法被目录时间捕获，采集前后须保持测试负载可控并记录干扰。比较器拒绝不完整、错误、身份不符、时间重叠、重复条目、同对象矛盾元数据和私密额外字段。

## 集中验收顺序

1. 对可重取测试内容建立 before，记录当前操作关联和保留项状态。
2. 按现有产品操作触发清理，收取 API 回执，再建立 after；对照条目消失、替换、内容身份变化及逻辑长度。
3. 正常重新浏览，确认缓存能够重建；在限制模式重复同一负载，比较新增条目和写入状态。
4. 关闭限制后重复负载，确认原写入恢复。三轮保持相同 owner/安装条件；变化则重新建立证据，不串用旧快照。
5. 登录、下载、草稿及唯一副本的业务保持由实际业务状态验证。网页只限定 DiskCache，不清 Cookie 或其他站点数据。

比较结果的 `removedObservedLogicalBytes` 只代表两次观察间消失的对象逻辑长度。`allocatedStatDelta` 来自 st_blocks，不能消除 APFS clone、压缩和延迟回收影响；`physicalRelease` 固定为 notMeasured。因果归属仍需 owner、操作关联和受控负载证据，程序不会把文件消失自动标为插件释放成功。

开发侧测试入口 `python tests/test_owner_snapshot.py` 包括脱敏比较边界及 POSIX 实际文件、硬链接、非 UTF8 名称、NOFOLLOW、删除重建和预算失败。Windows 上 POSIX 项明确跳过；云端实际执行结果与手机验收分别记录。

实际非 UTF8 名称夹具若被底层文件系统以 EINVAL、EILSEQ 或 ENAMETOOLONG 拒绝，会单独输出 UNSUPPORTED 并继续其余真实文件检查；不能将该名称能力计为已验证。其他创建错误仍使测试失败。
