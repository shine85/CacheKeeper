# 0.7.2-230.1 锁阻塞修复与实测

## 这次修复了什么

用户补充故障发生在百度网盘滑动照片时。`1120-03.json` 来自 228.1；图片采集 clean 阶段没有提交 SDK 清理，报告也没有线程栈。因此，本轮修复的是已在开发侧复现的插件阻塞缺陷，尚未确认它们就是目标手机滑图卡住的实际原因。

| 发现 | 修复 | 实际验证 |
|---|---|---|
| 图片回执持有前台也要用的引擎锁，等待上下文锁和写盘 | 快照与落盘按独立发布锁排序，写盘在引擎锁外执行 | 固定 228.1 精确阻塞反例；新版持住回执 I/O 时前台可撤销限制、读状态及转交原写入 |
| 网络全局状态锁覆盖系统容量 getter/setter | 系统调用移出全局锁，按请求、策略、写完成顺序维护恢复状态 | 旧版 setter/getter 两个锁阻塞反例；同实例、跨实例、旧写晚到、开关交错、异常和原整组初始化回归通过 |
| 首轮重构使异常初始化临时状态污染全局 | 成功初始化才提交内部临时状态；明确请求和成功独立对象保留 | 失败接收者保活、跨线程零/非零请求及嵌套对象对照通过 |
| 解锁后旧通知可能读到尚未写盘的终态并提前结束后台任务 | 通知及调度完成均使用已完成 observer 的快照 | 阻住终态写盘时后台任务保持，放行后真实落盘、恰好结束一次；对应精确反例通过 |

## 手机集中实测

1. 安装 230.1 后，按包管理器提示完成加载。保留报告里的百度“只清理”模式，退出百度后重新打开一次，进入此前卡住的照片页面，连续来回滑动 30–60 秒；确认能滑动、点击、退出照片页。
2. 若第一步正常，把百度切到“限制缓存并清理”，再打开同一照片页面浏览，并打开几张此前未查看的照片；确认页面与图片回调正常。回到后台等待清理完成。
3. 关闭百度的应用开关，再回百度浏览并打开新照片；确认正常加载与滑动，之后可恢复原来的“只清理”设置。
4. 只需反馈三步是否正常；若仍卡住，说明在哪种模式、照片页是否还能点击退出。保存一份新的普通诊断到 `packages/采集报告` 即可，先前预检和容量测量不必重跑，也不需要重开集中采集向导。不要删除下载、清空账号或退出登录作为测试动作。

## 最终目标尚缺什么

本轮推进现有清理与限写的宿主可用性和关闭恢复，没有新增五 APP 私有主体清理能力。Gurd 真实清理范围与全写入保护，QQ、京东、百度 Documents 主体及 Swiftgram 私有资源契约仍未闭合；这些不能用局部图片 SDK 成功代替。百度滑图故障需要本次具体场景验证，仍失败时按新现象定位，不能把同一套采集反复执行当作修复进度。
