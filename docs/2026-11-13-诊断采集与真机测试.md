# 快速采集诊断与手动导出

本页描述快速采集修复后的版本。旧 0.7.2-95.1 的“补采已配置 APP”会逐目录深度检测，已由新的记录汇总流程替代。

## 操作步骤

1. 安装新版，按安装器提示完成重新加载，打开“设置 → 缓存管家 → 诊断”。
2. 点“采集诊断”。后台只读取插件已保存的配置、目录和清理等记录；进度按 APP 固定，例如 0/126 到 126/126，不会追加数百个深度任务。
3. 等待“报告仅在内存”的完成提示。此时没有自动创建报告文件，也不会自动打开分享。
4. 需要保存时，手动点“导出报告”，在分享菜单选择“存储到文件”，将 JSON 附件发回会话。

采集不会发起目录检测、深度检测或清理，也不会覆盖或取消其他页面已有请求。原有清理回执按插件既有功能维护；汇总只读取这些记录，不另存诊断日志。确实缺新证据时，只在具体 APP 的目录页检测需要的范围，再返回采集。

## 内存与保存边界

- 采集结果只存在当前页面内存中；离开页面会释放，重新进入需要再次采集。
- 只有点“导出报告”才生成临时 JSON；分享结束（包括取消）后清理临时副本。
- 你主动保存在“文件”或其他目标中的副本会保留，由你管理；无自动上传。
- 重复点击不并发生成报告；生成期间可以返回，后台结果不会再弹出分享或写报告文件。

## 报告口径

- 保留 APP/系统/插件版本、配置、目录扫描、历史趋势、清理回执、网络和主动诊断结果，以及已有深度档案。
- 原记录时间、缺失、损坏、取消、失败和覆盖/截断标记不变。采集完成表示汇总结束，不表示这些目录刚刚重新扫描或全部清理。
- 新报告 `schemaVersion=2`，`collection.mode=savedRecords`，`rescanned=false`，`total/completed` 按 APP 计数。旧报告的扫描任务字段不再生成。
- 不读取应用文件内容、原始日志或设备标识；未知路径组件、账号段和资源标识匿名化。APP 名称和已知技术目录仍可见。
- 记录中的逻辑字节、历史累计清理量和系统存储总占用不是同一个口径，不能相减得到当前可释放空间。

## 真机验收

确认采集能结束、APP 总数固定、采集后未自动保存；点击导出才出现分享。再测试取消分享后可重试、边缘返回拖到一半再取消仍可操作、真正离页重进没有上次内存报告。反馈“采集耗时：约多少秒；是否自动保存：是/否；导出：成功/失败”，附手动导出的 JSON。

首页搜索仍需验证“百度”、`baidu`、Swiftgram 的输入/过滤和清空重输。百度 PDF 的离线/云端恢复、Swiftgram 媒体与主库的边界仍需单独证据，不因快速采集完成而宣布适配。
