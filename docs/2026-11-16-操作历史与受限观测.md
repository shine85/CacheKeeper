# 操作历史与受限观测

本说明承接 [154.1 真机反馈续修计划](superpowers/plans/2026-11-16-154-feedback-and-product-completion.md)。当前整组处于开发和审查阶段；没有新的原生、RootHide 编译、deb 或手机验证结论。

## 诊断如何关联一次操作

图片与网页组件共用插件实现中的进程实例标记。它只用于关联，不是认证凭据；`firstObserved` 是首次建立记录的时间，不是系统进程启动时间。一次组件触发分配事件号，各实际缓存实例获得子操作号；不同组件的前后台通知不被伪装成同一个事件。

事件保留触发来源、当时的配置与安装代际、刷新结果及有限原因。子操作区分排队、已提交、API 完成、跳过、失败和结果未知。晚到与重复回调只能更新原动作，不能把关闭后的当前状态改成旧动作完成。SDK 完成回调仍以 `bytesState=notMeasured` 表示没有单独测量空间收益。

同一组件保存当前与至多上一个进程实例的历史；旧实例未终结动作转为结果未知，不能由缺少回执推定已退出或清理成功。终态事件最多 32 个，终态子操作最多 64 个；活动请求继续服从原引擎的 in-flight 约束。较早记录被裁剪时明确标记截断。

旧记录在后台有界读取并校验，再与启动期间已发生的新事件合并。损坏历史明确记录为拒绝，不影响当前授权判断。写入失败保留待写的累计记录，沿组件串行顺序重试；记录本身不授予资源访问或清理资格。

## 保存记录与分享报告

本地组件回执保存内部关联，诊断导出对整份报告使用同一个匿名编号表。因此相同进程在图片、网页和其他记录里的关系仍可比对，原始内部 UUID、指针、路径和安装指纹不会作为操作历史导出。导出不触发新动作，不刷新原来的观察时间，也不把匿名编号重新用于原始身份校验。

[全 APP 大占用清单](2026-11-16-全APP大占用清单.md) 先校验原始 SDK 回执，再取有限状态与计数摘要。SDK 名称、API 完成次数和历史记录均不能单独证明某个容器或资源可删。实际文件变化由 [资源前后核验](2026-11-16-SDK资源前后核验.md) 及获准设备操作另行证明。

## 本轮受限观测的用途

百度图片来源检查增加首个拒绝阶段与有限加载关系；安装检查增加同次路径、FD 和实际调用来源的关系。仍保留原有来源、ABI、方法窗口、helper、安装身份及时间变化拒绝条件。尚未解析的关系保留未解析状态，稳定时间差也不自动当合法。

这些观测需要同一手机的新候选版本运行证据才能解释两处实际拒绝。它们不是百度已完成适配的结论。Swiftgram 原始文件名遍历修复同样需要新的深检报告确认，隐藏条目和证据截断仍分别报告。

## 验证与后续

开发回归包括真实保存 plist 到生产诊断再到 JSON、跨组件共享匿名关系、真实子进程重启、晚回调、重复回调、配置关闭、排队后排除、写失败重试，以及现有真实 SDWebImage 集成用例中的动作历史。固定旧源码必须命中指定行为断言，编译或超时失败不能算旧行为已复现。

Windows 原生入口明确为 UNAVAILABLE；最终需要同一整组提交在 macOS 上运行原生、三版 SDK、UIKit 回归，完成 SDK 16.5 RootHide 双架构编译及验包后，再准备一次明确范围的候选安装与定向采证。新包安装、资源动作及 iOS 16/17 真机效果均未由本说明验证。
