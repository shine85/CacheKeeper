- 用户确认搜索正常。本次只导出诊断，没有点击“检测全部”，因此旧扫描时间不能作为扫描失效证据。
- Swiftgram 的新 `SystemData` 深检回执：目录打开后，在枚举路径映射阶段停止；`files=0`、`failures=1`、`coverageComplete=false`。没有原始枚举路径，不能断言是哪一种 RootHide 别名导致。

- 当前工作从 `d823af8` 的干净工作区开始。原连接在 Stage 14 后断线，旧队列未重启。网络恢复后，新会话补齐 Stage 15–17，全部通过前后身份、镜像头与完整退出回执核验，随后正常关闭；未执行缓存动作。

| 回执来源 | 从 `control` 向编译参数注入完整包版本，新回执携带实际发出代码的版本及首次观察时间 | 旧回执继续可读且不补造新版本；无效或私密附加字段拒绝；图片和网页使用同一安装校验投影 |

## 固定源码与差异边界

- 现有适配契约依照 [SDWebImage 5.21.7](https://github.com/SDWebImage/SDWebImage/tree/2de3a496eaf6df9a1312862adcfd54acd73c39c0) 和已有 5.15.5 固定测试来源；配置提供队列属性，但仍须在真实初始化前后核验，不能由返回后的配置猜测历史队列。
- 对照 [SDWebImage 5.10.4 初始化](https://github.com/SDWebImage/SDWebImage/blob/a6b6e44eadf0d39250c10a7cc0e3b91d0bdb0e94/SDWebImage/Core/SDImageCache.m) 与[配置定义](https://github.com/SDWebImage/SDWebImage/blob/a6b6e44eadf0d39250c10a7cc0e3b91d0bdb0e94/SDWebImage/Core/SDImageCacheConfig.h)：旧接口没有 `ioQueueAttributes`，采用固定串行队列创建。百度静态接口存在相同差异，但这不能认定其准确 SDK 版本，也不能替代调用目标绑定、完整实现和真实 owner 的核验。

已完成的只读补采每批均核对安装路径、文件身份及前后镜像头哈希。断线后复用 Stage 1–14 的有效证据，新会话仅补 Stage 15–17 的必要依赖，未重放旧批次。没有执行设备缓存清理、写入限制、安装或设置修改。

## 旧契约实现与待构建检查点

- 图片 Hook 发布不再在安装后把全部当前 IMP 重新当作可信来源。保留核验时的实现，只替换四个自有 wrapper；原实现或最终实际实现发生变化时拒绝资格，保留外部 Hook 调用链。独立 runtime fixture 覆盖正常发布及三个并发变化拒绝场景；它不是实际 SDWebImage 行为测试。
- 显式区分 `Modern` 与 `FixedSerialLegacy`。旧契约要求第 11 槽缺席并持续复核，初始化及对象观察不调用不存在的 getter。标准 backend、KVO 配置、队列、路径、安装身份、授权与保留范围的门均保留。
- 生产来源候选核验主镜像、包版本、UUID、真实映射保护、节边界及 24 个原 IMP 的位置与窗口 SHA256；来源采样与随后 ABI 核验使用的 IMP 必须一致。两个 `SDFileAttributeHelper` 方法已完成 804 与 548 字节窗口、精确 ABI、自有元类方法和实际 `libSystem` 导入绑定核验。来源门检查全部 26 个窗口共 5,788 字节，临时等待条件已移除；这仅完成源码准入条件，**百度真实 owner 与清理、限制、关闭恢复仍待真机回执**。
- 真实 5.10.4 fixture 已实现 15 个常规用例和 1 个缺席 API 变更用例，两组在独立进程运行。首次 Legacy Hook 安装前，用同一引擎真实 Modern 准入流程断言 `unsupported / missingMethod / 11`。旧源码 RED 只选择一个真实 admission 断言，编译失败或其他失败不算 RED。原 5.21.7、5.15.5 各 30 个用例保留。
- CI 已接新增真实 SDK 构建、精确 revision 校验、独立结果包与 RED 证据附件。整个 job 上限调为 60 分钟；单项断言与原有测试期限保持。来源校验原生测试已接总入口，合成映射及自有元类只验证读取、布局、ABI、方法归属与指纹边界，不宣称百度运行时阳性。新增运行门夹具仅替换来源/helper 边界，实际执行 Objective-C 调度、文件范围、排队和失败恢复，用于验证辅助方法变化时立即恢复原写并取消排队清理；不替代真实 SDK 测试。运行门只复核两个 helper，不在每次写入时重扫 24 个主方法窗口。

本地实际结果：版本测试 1/1、编排 35/35、13 个改动 Python 文件语法解析、冻结源码核对及四类本地目录忽略规则均通过；`git diff --check` 通过（保留 CRLF 转换提示）。原生入口、来源单测与运行门单测入口均为 exit 2 / `UNAVAILABLE`，UIKit 与旧 SDK RED 入口均为 exit 1 / `UNAVAILABLE`；没有执行原生、UIKit、真实 SDK 或 Theos 编译。旧契约及首次 Modern 探针独立审查未发现确定 P1/P2，不能替代运行测试。

## 仍需闭合的最终能力

Swiftgram 深检路径问题需在新包重新检测后确认；安装身份补采仍可能明确拒绝，不能因加入诊断就宣称百度网页缓存失败已修复。Swiftgram 的消息数据库与共享媒体不能混作可清缓存；百度下载副本也不等同图片 SDK 缓存。私有资源动作仍需要真实 owner、调用队列、完整保留集合、恢复来源和逐项结果；未取得这些条件前保持未知范围。三轮必要数据保持、关闭恢复与 iOS 17 真机验证分别记录，不能用静态接口发现或编译成功代替。
