## 当前通用清理规则

1. **启用与发现分开。** `enabled` 决定该 APP 按配置是否应执行；自动发现只登记目录，不自动开启 APP。总开关、模式和子开关是配置事实，实际生效须有当前版本宿主回执与行为证据。
2. **通用候选只到平台缓存用途。** 主容器的 `Library/Caches` 与 `tmp` 可进入平台缓存清理判断；`Caches`、`Cache`、`cache`、`.cache` 等名称用于发现，不能单凭目录名授予删除权限。删除仍须逐文件满足配置、排除、保留、完整读取、身份稳定、文件年龄与生命周期条件；普通清理检查至少 60 秒文件年龄，相关生命周期条件也须单独满足。
3. **保留优先。** 用户排除、内置保留和必要状态优先于通用规则。Documents、偏好、账号、凭据、Cookie、下载、离线、收件及草稿等必要用途保留。平台缓存内的 SQLite 或图片格式本身不等于必要数据；平台缓存外的同名文件、数据库或媒体也不因此取得删除授权。
4. **共享只计量。** Group 共享容器仅登记、分类和测量，不执行通用删除或目录写锁。Swiftgram 的 postbox、db、media、media/cache、logs 是结构标签，不能据此删除共享数据。`Application Support`、`HTTPStorages`、`SplashBoard`、`Saved Application State`、`Logs` 等混合用途目录没有整目录通用删除授权；未知私有资源保留并记录适配缺口。
5. **模式边界。** `clean` 不请求限写；`auto` 与 `prevent` 在当前策略中均请求限写，使用同一清理引擎。NSURLCache 还受 `urlCache` 开关控制，图片限写按模式判断，不能用 NSURLCache 开关代替图片行为结论。WebKit 由单独开关与宿主 API 回执判断，不对 `Library/WebKit` 做通用递归删除。
6. **私有与日志契约。** 当前唯一内置可清私有规则是抖音 `douyin-alog` revision 3，仅匹配 41.1.0 的 `Library/alog`；41.2.0 版本失配时保留，且不回退到通用日志规则。日志定级只允许符合条件的未知目录，限定日志文件名且无数据或媒体证据；本次摘要没有任何 APP 的非空 `logPaths`。
7. **容量口径。** 关联根占用为 `registeredAllocatedBytes`，不是缓存量、可清理量或实际回收空间。共享根可能同时关联多个 APP，禁止跨 APP 相加。特殊节点可能包含父子关系，也不能相加。0 B、未登记根、未提供字段均不代表已完整测量、没有数据或已验证无问题。

依据：[策略定义](../AxsCacheKeeperPolicy.h)、[逐文件清理规则](../AxsCacheKeeperCleanupRules.m)、[执行检查](../Baseline.m)、[生命周期检查](../Scanner.m)、[资源分类](../AxsCacheKeeperResourceLayout.h)、[图片准入](../AxsCacheKeeperImageCache.m)。内置保留例外还包括微信资源目录、TikTok 离线与导入编辑目录、Spotify 缓存、Google Maps 与 Strava 离线目录；这些例外是保护规则，不是私有清理适配。
