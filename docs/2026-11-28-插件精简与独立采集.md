# 插件精简与独立手机采集

目标：插件只承担清理、限制写入、关闭恢复、用户配置及普通结果展示；开发采集退出插件，在手机解压工具包后运行一次，自动生成一份脱敏 JSON。

## 实现方案

用户已要求直接实施并明确不要插件内采集。采用独立签名 Objective-C/Foundation 命令行工具与短 shell 启动入口，复用现有只读诊断投影。手机不依赖 Python、jq、动态注入或附加进程。隐藏现有按钮会留下策略覆盖和后台流程；继续扩展原向导违反本轮目标，因此不采用。

插件移除 CollectionSession/Return/History、HostPreflight 和 ImageCollection 的页面、路由、请求生产及宿主临时策略覆盖。旧采集记录不删除，旧回执的字段仍可只读解析。保留图片写入观察、操作历史、权限/身份/资源范围检查、SDK 正常策略执行和关闭恢复；清理历史不属于采集历史。

工具在一个有界窗口内读取插件已有脱敏技术状态，并记录目标进程的系统存活元数据（kern.proc SPI，访问失败明确报告）、系统已生成故障记录的有限元数据。报告区分即时采样与已有记录，记录读取失败和缺失，不宣称已完成私有接口适配或取得卡顿堆栈。它复用现有系统注册和容量算法自动识别全 APP 占用，只读取目录和 stat 元数据；测量超时或权限不足保留明确的未覆盖范围。它不修改 APP 配置、不清理资源、不启动 APP、不读取第三方进程内存或业务文件内容，不触发新的系统采样。

## 实现计划

- [x] 更新真实 Runtime/UI 回归：旧采集请求不得改变普通配置或跳转页面；保留清理、限写、关闭恢复、异步回执发布与生命周期用例。
- [x] 删除插件采集闭包和对应专属测试接线，维护旧回执解析兼容；移除根页和单 APP 页的开发采集入口。
- [x] 实现独立手机工具：默认后台有界采样，唯一报告文件，固定脱敏字段，权限不足/损坏记录/写入失败显式报告；测试真实文件与进程边界。
- [ ] CI 运行核心原生、UIKit、容量及工具真实行为；构建 RootHide 插件和独立工具 ZIP，验明双架构、签名、包身份、附件内容及无开发采集类。
- [ ] 整体独立复核后统一提交推送，跟进同一 SHA 的完整 Actions，再给成功包、工具下载和一次性操作步骤。

## 回归重点

1. 现有 appEnabled/directories 配置字节不变，遗留 imageCollectionRequest 不生效；正常配置通知和自动清理继续执行。
2. 图片三套已支持 SDK 的真实写入限制、关闭恢复及必要资源范围门不变；未验证私有主体仍保持保护。
3. 切前后台和重新进入设置不重建采集页；扫描、搜索、一次性清理和清理历史仍可用。
4. 工具只写自身报告目录；只输出白名单技术字段，错误不泄露完整路径或任意自由文本；重复运行互不覆盖。
5. 所有编译、模拟器/原生行为与目标手机实测分别报告。百度滑图卡顿及五 APP 私有主体能力不能因工具可运行而标记已修复。

新文档，无旧文件可备份。既有文件修改前分别保存在本轮 `BK/` 时间戳目录。


## 当前实施与验证边界

已实施插件采集拆除、普通状态保留、网络探针退役，补足图片 Runtime 注册时已在后台的清理触发。独立工具包含全 APP 注册容量计划、有限目录/stat 测量、90 秒进程观察、已有故障元数据变化和脱敏技术状态；只运行一个入口。项目实际的未知私有资源保护保持有效，尚未解决 Gurd 完整候选谓词、QQ/京东/百度主体及 Swiftgram 私有缓存契约，也未证明百度滑图卡顿已经消失。

本地已执行 iOS 16.5 arm64 对象编译（13 对象退出 0）、42 UIKit 编排、17 原生编排、6 清理摘要编排、4 Runtime 编排、8 XCTest 宏用例与源检查。独立工具 Foundation、UIKit 和 RootHide 最终链接/签名仍须同提交云端执行；Windows 明确 UNAVAILABLE，不能代替真实行为验证。独立审查发现的测试属性误替换和已删除按钮的残余提示已修。

工具使用步骤：解压 `CacheKeeper-Diagnostics-版本.zip`，在解压出的 `CacheKeeper-Diagnostics` 目录运行 `sh run.sh`。看到 started 后正常使用手机，约 90 秒后回传该目录 `reports/CacheKeeper-唯一标识/report.json`；不需要在插件里切模式、选五 APP 或重复导出。目标手机实际运行结果独立记录。
