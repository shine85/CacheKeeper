# 开源调研核查与适配依据

日期：2026-11-15。此文区分已读取的源代码、实现选择与仍需验证的设备行为。第三方源码未复制进产品，未引入沙箱逃逸或系统目录清理。

## 对用户调研草稿的核查

草稿可用于比较路径检查、身份绑定和失败诊断，但以下结论需要修正：

- CacheKeeper 已有目标 APP 进程内实现：`Cleaner.m` 核验容器和配置，`AxsCacheKeeperNetworkCache.m` 已控制 NSURLCache 的初始化、容量设置与共享实例替换。草稿“仅设置面板、不注入 APP，因此需要另作架构决定”的前提不成立。
- 指定查询未命中只能证明这次检索未找到；不能据此断言没有人做过缓存写入 hook 或限制。
- 别的清理器说明离线内容会重下，可作为告知文案参考，不能证明本机某个资源当前仍有恢复来源。缓存目录、草稿、唯一副本和用户保留仍由当前契约判断。
- 全量预检查后再逐项检查不是原子事务，仍可能部分完成。逻辑字节和 API 完成均不等于物理释放。

本次重查了 WQFiles、WQManager 的相关源码；没有将草稿中其他四仓、星标数或检索数量当作已重新核验的事实。

| 固定来源 | 确认机制 | 本项目采用方式 |

## SDWebImage：落实清理与减少写盘

已实际读取并对比 [5.21.7 固定提交](https://github.com/SDWebImage/SDWebImage/tree/2de3a496eaf6df9a1312862adcfd54acd73c39c0) 与 [5.15.5 固定提交](https://github.com/SDWebImage/SDWebImage/tree/fb50c1d20f24db5322b2f8f379de3618f75fe08e)。本地已采移动云盘、威锋、米家的 SDK 镜像提供关联到真实类的方法编码，包含初始化、diskCache/config/path/ioQueue getter、setData/setExtendedData 和 removeAllData；这是静态 ABI 依据，不等于本次运行实例已通过。

- [初始化](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDImageCache.m#L118) 创建各实例真实 IO 队列并复制配置。观察 APP 自己的返回对象，不创建替代默认缓存。
- [容量语义](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDImageCacheConfig.h#L89) 中 `maxDiskSize=0` 表示不限，不能照搬 NSURLCache 的置零用法。
- [写盘入口](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDDiskCache.m#L90) 可对已准入的实际 backend 限制 payload 与扩展属性写入。原来的内存写入、完成回调和关闭后的原实现保持可用。
- [官方清理](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDImageCache.m#L780) 在该 owner 的 IO 队列调用 `removeAllData`。本实现将插件工作排入同一队列，等实际执行时再次核对最新授权，再同步调用 backend，避免再次排队后无法取消。
- [默认队列配置](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDImageCacheConfig.m#L38) 在 5.21.7 为串行自动释放池属性，5.15.5 为 NULL；非 NULL 不等于并发。未知属性、自定义后端/文件管理器与初始化后配置漂移拒绝。
- [removeAllData](https://github.com/SDWebImage/SDWebImage/blob/2de3a496eaf6df9a1312862adcfd54acd73c39c0/SDWebImage/Core/SDDiskCache.m#L133) 删除后重建整个缓存根，且忽略底层错误。因此父/子排除、APP 保留和依赖任一重叠都必须拒绝整个 owner；回执只计 API 返回，不虚报删除文件或释放字节。

适配仅覆盖当前 APP 已授权 Library/Caches、tmp 的专用子目录，复用总开关、三模式、自动发现、目录选择和排除。未开始执行的工作可因关闭、前台、超时而撤销；已经开始的同步删除不能回滚。相同或重叠目录的多 owner 不视作独立串行安全。

## 剩余资源契约

[Kingfisher 7.12.0](https://github.com/onevcat/Kingfisher/blob/2ef543ee21d63734e1c004ad6c870255e8716c50/Sources/Cache/ImageCache.swift#L662) 有有限 ObjC 过期清理入口，但全量磁盘清理和 memory-only 控制涉及 Swift owner、泛型/枚举/闭包契约，不能套用 SDWebImage 的方法签名。

[Swiftgram MediaBox](https://github.com/swiftgram/Telegram-iOS/blob/ba54d9823d413f9816e5eee2724da77d5079f4cf/submodules/Postbox/Sources/MediaBox.swift#L1782) 的队列、保留集合和删除实现已结合保存镜像分析；实际账户/MediaBox owner、Swift 调用 ABI、资源恢复来源仍未闭合。返回 resource IDs 也不证明 unlink 成功。百度非标准下载副本同样需要自身事务契约。这些大占用不会因新增图片 SDK 适配而自动获得删除资格。

本轮范围和执行证据继续记入[整组计划](2026-11-15-开源缓存接口与整组功能完善.md)，不重复连接 SSH。
